# 클로드코드(Claude Code)로 이어서 작업하기 — 시작 가이드

> 작성: 2026-09-17
> 이 문서는 지금까지 Cowork(이 채팅)에서 진행한 "장비구성뷰" 웹앱 작업을 컴퓨터에 설치하는 클로드코드(터미널 CLI 도구)로 옮겨서, 여기서 하던 것과 똑같이 대화하면서 이어서 수정할 수 있도록 준비한 패키지입니다.

---

## 1. Cowork(여기)와 클로드코드는 뭐가 다른가

| | Cowork(지금 이 채팅) | 클로드코드 |
|---|---|---|
| 실행 위치 | Anthropic이 관리하는 임시 클라우드 공간 | 사용자 컴퓨터(맥/윈도우/리눅스)에 설치, 터미널에서 실행 |
| 파일 | 이 세션에서만 존재. 대화가 끝나도 파일은 남지만, 로컬 폴더처럼 탐색기에서 바로 열리진 않음 | 지정한 실제 폴더의 실제 파일을 직접 읽고 수정 |
| 대화 방식 | 지금처럼 자연어로 요청하면 파일을 만들고 다운로드로 전달 | **완전히 동일하게** 자연어로 요청하면 그 폴더 안 파일을 직접 열어서 고침 |
| 버전 관리(git) | 없음 | 있음 — 원하면 매 작업을 커밋으로 남겨 변경 이력을 추적 가능 |
| 적합한 용도 | 프로토타이핑, 단발성 파일 작업, 결과물을 다운로드로 받아보는 흐름 | 계속 이어가는 실제 개발 작업, 여러 파일이 얽힌 프로젝트, 이력 관리가 필요한 작업 |

**핵심**: 클로드코드도 지금 이 채팅과 똑같이 "이 보드 이미지 좀 키워줘", "SICAS 랙에 새 측정지점 추가해줘" 같은 자연어 대화로 작업을 이어갈 수 있습니다. 차이는 대화 상대(Claude)가 클라우드가 아니라 사용자의 실제 컴퓨터 폴더에서 직접 파일을 읽고 쓴다는 것뿐입니다.

**중요 — 두 환경은 이제부터 별개의 사본입니다.** 이 패키지를 컴퓨터에 내려받아 클로드코드에서 수정하기 시작하면, 그 폴더의 파일과 이 Cowork 프로젝트("고장분석 프로그램")의 문서는 서로 자동으로 동기화되지 않습니다. 클로드코드에서 고친 내용을 이 프로젝트에도 반영하고 싶다면, 나중에 그 파일을 다시 업로드하거나 내용을 복사해 이 채팅에 붙여넣어야 합니다. 반대로 이 채팅에서 계속 작업한 내용도 클로드코드 폴더에는 자동 반영되지 않습니다. 둘 중 하나를 "메인"으로 정하고 쓰는 것을 추천합니다.

## 2. 패키지 안에 들어있는 것

```
장비구성뷰_프로젝트/
├── 장비구성뷰_v3_시안.html          ← 완성된 앱 본체 (더블클릭하면 브라우저에서 바로 열림)
├── board-info.json                  ← 보드/LED 정보 데이터 (앱에 이미 내장되어 있음, 참고/편집용 사본)
├── rack-layout.json                 ← 랙/캐비닛 배치 데이터 (〃)
├── measure-points.json              ← 측정지점 데이터 (〃)
├── fault-cases.json                 ← 고장상황(장애사례) 데이터 (〃)
├── photo-markers.json               ← 사진별 마커 좌표 데이터 (〃)
└── claude/
    ├── device-connections.json      ← 시스템 지도 노드/엣지 데이터 (앱에 이미 내장되어 있음, 참고/편집용 사본)
    ├── board-face.json              ← 보드 LED 좌표 오버레이 데이터 (〃)
    ├── photo-guide.json             ← 사진 촬영 가이드 (앱이 직접 읽지는 않는 참고 문서)
    ├── 장비구성뷰_확장가이드.md       ← 새 장비군을 추가하는 방법 정리 문서
    ├── 마커진행상황_점검_2026-09-05_아카이브.md ← 마커 작업 이력 아카이브
    ├── CB박스_배선도_추가_인수인계서_2026-09-16.md
    ├── 장비구성뷰_UI개선_인수인계서_갱신본_2026-09-16.md  ← 지금까지의 전체 개발 이력(§1~§23) + 다음 세션 체크리스트
    └── 클로드코드_시작가이드.md       ← 지금 읽고 있는 이 문서
```

**꼭 알아둘 것 — `장비구성뷰_v3_시안.html` 하나로 완결된 앱입니다.** 위 JSON 파일들(`board-info.json`, `rack-layout.json`, `device-connections.json`, `board-face.json`, `measure-points.json`, `fault-cases.json`)의 내용은 이미 이 HTML 파일 안에 자바스크립트 변수(`BOARDINFO_RAW`, `RACK`, `CONN`, `BOARDFACE`, `MPOINTS`, `FCASES`)로 그대로 박혀 있습니다. 그래서 HTML 파일 하나만 있어도 앱이 완전히 동작합니다. JSON 파일들은 "지금 데이터가 정확히 어떤 상태인지 한눈에 보고, 클로드코드와 대화할 때 참고 자료로 쓰기 위한" 사본입니다. `photo-markers.json`·`photo-guide.json`은 HTML에는 들어있지 않은 별도 데이터(사진 마커는 원래 브라우저에 임시 저장되는 방식)라 파일로만 존재합니다.

즉 데이터를 수정할 때는 클로드코드에게 "board-info.json 고쳐줘"라고만 하면 안 되고, **"HTML 안의 BOARDINFO_RAW도 같이 갱신해줘"**까지 챙겨야 실제 앱에 반영됩니다. 이 부분은 아래 3번 항목에서 더 설명합니다.

## 3. 클로드코드 설치 방법 (2026년 9월 기준 공식 설치 명령)

### macOS / Linux / WSL

터미널을 열고:

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

### Windows (PowerShell)

```powershell
irm https://claude.ai/install.ps1 | iex
```

### Windows (명령 프롬프트/CMD)

```batch
curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd
```

> Homebrew(`brew install --cask claude-code`)나 WinGet(`winget install Anthropic.ClaudeCode`), npm(`npm install -g @anthropic-ai/claude-code`)으로도 설치할 수 있지만, 위의 네이티브 설치 스크립트가 가장 간단하고 자동 업데이트도 됩니다.

설치가 끝나면 확인:

```bash
claude --version
```

버전 번호가 뜨면 설치 성공입니다.

## 4. 시작하는 방법 (단계별)

1. **이 패키지를 통째로 압축 해제**해서 컴퓨터의 원하는 위치에 폴더로 둡니다. 예: `~/Documents/장비구성뷰_프로젝트/` (윈도우라면 `C:\Users\사용자이름\Documents\장비구성뷰_프로젝트\`).

2. **터미널(맥/리눅스는 터미널 앱, 윈도우는 PowerShell)을 열고 그 폴더로 이동**합니다.
   ```bash
   cd ~/Documents/장비구성뷰_프로젝트
   ```

3. **(선택이지만 강력 추천) git으로 변경 이력 추적을 시작**합니다. 처음 한 번만 하면 되고, 이후로는 클로드코드가 알아서 각 작업을 커밋해 달라고 하면 이력이 남습니다.
   ```bash
   git init
   git add -A
   git commit -m "초기 커밋: Cowork에서 작업한 장비구성뷰 v3 이관"
   ```
   (git이 없다고 나오면 macOS는 `xcode-select --install`, Windows는 [git-scm.com](https://git-scm.com/downloads/win)에서 설치)

4. **클로드코드 실행**:
   ```bash
   claude
   ```
   터미널 안에 대화창이 뜹니다. 처음 실행하면 브라우저가 열리며 로그인(Pro/Max/Team/Enterprise 계정 필요 — claude.ai 무료 플랜은 클로드코드를 지원하지 않습니다)을 요청합니다.

5. **이제 지금까지 이 채팅에서 하던 것과 똑같이 대화하면 됩니다.** 예를 들어:
   - "`장비구성뷰_v3_시안.html`을 열어서 SICAS 랙 구성을 보여줘"
   - "FTGS 그룹에 새 측정지점을 추가하고 싶어. `claude/장비구성뷰_확장가이드.md`를 참고해서 진행해줘"
   - "`claude/장비구성뷰_UI개선_인수인계서_갱신본_2026-09-16.md`의 §23 체크리스트에서 아직 안 끝난 항목들을 보여줘"

   클로드코드는 로컬 파일을 직접 읽고 고치기 때문에, "이 파일을 다운로드해줘" 같은 요청은 필요 없습니다 — 수정한 파일이 바로 그 폴더에 저장됩니다.

## 5. 이 채팅(Cowork)과 다르게 신경 써야 할 부분

- **`Projects` 도구(project_read/project_write)는 클로드코드에는 없습니다.** 이 채팅에서는 "고장분석 프로그램" 프로젝트의 문서들을 자동으로 읽고 썼지만, 클로드코드에서는 전부 로컬 폴더 안의 `Read`/`Edit`/`Write` 파일 도구로 대체됩니다. 이 패키지 안에 필요한 문서를 전부 넣어뒀으니, "장비구성뷰_확장가이드.md 참고해서 진행해줘"처럼 파일명을 말해주면 됩니다.

- **HTML에 데이터가 내장되어 있다는 점을 계속 챙겨야 합니다.** 예를 들어 `board-info.json`만 고치고 끝내면 실제 앱 화면에는 반영되지 않습니다. 클로드코드에게 요청할 때 "board-info.json도 고치고, 장비구성뷰_v3_시안.html 안의 BOARDINFO_RAW 변수도 동일하게 갱신해줘"라고 명확히 말하거나, 애초에 "HTML 파일의 BOARDINFO_RAW를 직접 수정해줘"라고 하는 편이 더 확실합니다. (JSON 파일 자체를 굳이 최신으로 유지하지 않아도 앱 동작에는 지장 없습니다 — 다만 나중에 헷갈리지 않으려면 같이 갱신해두는 걸 권장합니다.)

- **사진/마커 데이터는 브라우저 로컬저장소(localStorage) 기반입니다.** `photo-markers.json`은 이 채팅에서 스냅샷으로 내려받은 사본일 뿐, 앱이 실제로 쓰는 최신 마커 데이터는 각자 사진 작업을 했던 브라우저에 남아 있습니다. 새로운 마커 작업 결과(`photo-markers-export.json`)를 병합하고 싶으면 그 파일을 클로드코드에 가져와 "photo-markers.json에 병합해줘"라고 요청하면 됩니다.

- **git 커밋을 습관화하면 좋습니다.** 클로드코드가 파일을 여러 번 고치다 보면 실수로 되돌리고 싶은 순간이 생길 수 있습니다. 의미 있는 변경 단위마다 "지금까지 변경사항 커밋해줘"라고 요청해두면 언제든 이전 상태로 돌아갈 수 있습니다.

- **동일한 결과물이라도 전달 방식이 다릅니다.** 이 채팅에서는 파일을 만들면 다운로드 카드로 전달했지만, 클로드코드에서는 폴더 안 파일이 곧 결과물이라 별도 "다운로드" 절차가 없습니다. 대신 그 폴더를 그대로 열어보면 됩니다.
