## 요청 배경

기존 C/B박스 4종(`FTGS_CB_UNI`/`FTGS_CB_BI`/`FTGS_CB_CENTERPAD`/`FTGS_CB_MIXED`) 이미지는 튜닝 유닛·인터페이스 모듈·전환 모듈을 사각 함체 안에 배치만 해두었을 뿐, 단자끼리 실제로 어떻게 연결되는지 보여주는 배선(전선)은 전혀 그려져 있지 않았음. 사용자가 각 이미지별로 정확한 단자 번호·연결 대상·색상을 지정해 4개 이미지 전부를 다시 제작 요청함.

## 공통 변경사항 (1차)

1. **정사각형 함체를 최대한 채우도록 재구성** — 튜닝 유닛·인터페이스 모듈·전환 모듈 크기와 여백을 조정해 이전보다 함체를 더 꽉 채움.
2. **인터페이스 모듈과 전환 모듈은 항상 같은 행(row)에 배치** — 기존 `FTGS_CB_MIXED`(혼합형)는 원본 HTML의 `<g transform="translate(60,343)...">` 인터페이스 모듈 그룹에 **닫는 `</g>` 태그가 누락**되어 있어서, 뒤이은 전환 모듈 그룹이 그 안에 중첩(nest)되어 좌표가 겹으로 밀리는 버그였음(사용자가 지적한 "인터페이스 모듈과 전환모듈이 같은 선상에 있어야 함" 문제의 실제 원인). 이번에 그룹을 완전히 독립시켜 두 모듈을 동일한 Y좌표·동일한 크기로 나란히 배치해 해결.
3. **함체 상단 테두리에 원형 단자 4개 신규 추가** — 왼쪽부터 D·C·B·A 순서로 동일 간격 배치. 오른쪽 튜닝 유닛(또는 유일한 튜닝 유닛)의 9·10번 단자는 항상 A·B로, 왼쪽 튜닝 유닛의 9·10번 단자는 항상 C·D로 굵은 검정선(두께 4.5, 나머지 결선은 1.8~2.6)으로 연결 — 다만 튜닝 유닛 본체와 겹치지 않도록 함체 좌우 여백(마진) 영역을 거쳐 우회시키는 직교선(수직·수평만 사용)으로 라우팅함.
4. **단자 간 배선은 전부 수직/수평만 사용**, 서로 다른 배선끼리 교차하는 것은 허용하되 평행하게 겹치는 구간은 각기 다른 깊이(depth)로 어긋나게 그려 최대한 피함.
5. **튜닝 유닛·인터페이스 모듈·전환 모듈 자체의 그림(내부 디자인)은 전혀 손대지 않고 원본을 그대로 재사용** — 배치(위치·크기)와 배선만 새로 그림.

## 이미지별 결선 요약

- **단방향용(`FTGS_CB_UNI`)**: 튜닝 유닛 2개(좌=수신측/우=송신측) + 인터페이스 모듈 1개(공용, 하단 중앙). 각 유닛의 2·7·8/3·11/4·5번 단자 묶음(검정) + 14→인터페이스 4번째 칸(빨강)·11→3번째 칸(파랑, 송신측) + 15→2번째 칸(회색)·20→1번째 칸(노랑, 수신측) + 9·10→C/B박스 단자(굵은 검정 계열).
- **양방향용(`FTGS_CB_BI`)**: 튜닝 유닛 2개 + 전환 모듈 2개(각 유닛 하단 개별). 양쪽 공통으로 2·7·8/3·11/4·5번 단자 묶음(검정) + 14→전환모듈 3번(빨강)·11→4번(파랑)·15→6번(회색)·20→5번(노랑) + 9·10→C/B박스 단자(굵은 검정 계열, 좌우 대칭).
- **센터패드용(`FTGS_CB_CENTERPAD`)**: 튜닝 유닛 1개(중앙) + 인터페이스 모듈 1개. 2·7·8번만 묶음(검정) + 14→4번째 칸(빨강)·11→3번째 칸(파랑) + 9·10→C/B박스 A·B만 연결(C·D 단자는 이 구성에서 사용 안 함 — 원 4개는 공통 규격대로 그려두되 미배선 상태로 둠).
- **혼합형(`FTGS_CB_MIXED`)**: 좌측 튜닝 유닛(단방향쪽)은 2·7·8만(검정) + 14→인터페이스 4번째 칸(빨강)·11→3번째 칸(파랑) + 9·10→C·D(굵은 검정 계열). 우측 튜닝 유닛(양방향쪽)은 2·7·8/3·11/4·5(검정) + 14→전환모듈 3번(빨강)·11→4번(파랑)·15→6번(회색)·20→5번(노랑) + 9·10→A·B(굵은 검정 계열).

## 2차 수정사항 (동일 세션, 사용자 피드백 반영)

1차 작업물에 대해 사용자가 스크린샷 2장과 함께 아래 3가지를 피드백하여 4개 이미지 전부에 재반영함.

1. **튜닝 유닛 내부 점퍼선(2-7-8, 3-11, 4-5 등)을 단자대 아래쪽이 아니라 위쪽(보드 몸통 안)으로 라우팅** — 모두 같은 색(검정)이라 어디서 어디로 연결되는지 안 보인다는 피드백. 색을 추가하는 대신(사용자가 명시적으로 배제) 간격(depth)만 크게 벌려(18/42/66/90 단위) 위쪽 여유 공간에 겹치지 않는 계단식 배선으로 재배치. `lib.py`의 `bus()`에 `direction="up"` 옵션을 추가해 구현. 단방향·양방향·혼합형 3개 이미지에 적용(센터패드형은 점퍼 묶음이 1개뿐이라 원래도 겹침이 없었지만 동일하게 위쪽 라우팅으로 통일).
2. **박스 제목을 가로 중앙 정렬** — 기존엔 좌측 정렬이라 좌측 마진을 타고 올라가는 굵은 배선(9·10→C/B박스 단자선)과 겹쳐 가려졌음. `box_template()`에서 `text-anchor="middle"`로 변경해 4개 이미지 모두 반영. **수신측/송신측(및 혼합형의 단방향쪽/양방향쪽) 라벨을 보드 바깥(위)이 아니라 보드 안쪽으로 이동**하고 글씨를 더 크고(15px) 굵게(bold) 변경 — 신규 `unit_label()` 헬퍼로 구현, 단방향용·혼합형에 적용. **양방향용의 "좌측"/"우측" 라벨은 요청대로 완전히 삭제**.
3. **D·C(및 A·B)로 가는 굵은 선을 색상은 유지하되 채도(명도)로 구분** — 9번 단자가 향하는 쪽(C 또는 A)은 순검정(`#000000`), 10번 단자가 향하는 쪽(D 또는 B)은 진회색(`#5a5a5a`)으로 통일. 좌/우가 아니라 "단자 번호"에 색을 고정했기 때문에 4개 이미지 어디서든 동일한 규칙으로 두 계열이 구분됨. 범례도 두 항목("9→C/B박스 …", "10→C/B박스 …")으로 분리 표기.

## 반영 위치

- 프로젝트 문서 `장비구성뷰_v3_시안.html`의 `BOARD_SVG` 객체 내 `FTGS_CB_UNI`/`FTGS_CB_BI`/`FTGS_CB_MIXED`/`FTGS_CB_CENTERPAD` 4개 키를 최종(2차 수정 반영) SVG로 교체 완료(다른 보드 키는 전혀 손대지 않음, 파일 총 줄 수 동일하게 유지되어 구조 훼손 없음).
- 동일한 최종 SVG 4개를 대화창에 파일로도 전달함(`C_B박스_단방향용.svg`/`C_B박스_양방향용.svg`/`C_B박스_센터패드용.svg`/`C_B박스_혼합형.svg`) — 1차 전달분은 이 2차 수정본으로 대체됨.

## 확인 필요(열려있는 항목)

- 이번 배선은 사용자가 말로 설명한 단자 번호·색상 지정을 그대로 도식화한 것이며, 실제 배선함 사진과 대조 검증은 아직 안 됨(본문 인수인계서 §23 체크리스트에도 이미 "실측 사진으로 좌우 배치·비율 검증 필요"로 남아있는 항목과 동일 맥락).
- 인터페이스 모듈의 "중앙 숫자없는 회색 칸"과 "번호(1~4) 붙은 회색 칸" 2종류 중, 이번 배선은 전자(번호 없는 칸)만 사용함 — 후자는 이번 요청에 포함되지 않아 계속 미배선 상태.
