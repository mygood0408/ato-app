# 세션 C 인수인계서 — 전원 경로 애니메이션 시범 (2026-09-29)

## 선행 조건
- 세션 B 완료(뷰어 존재) + B에서 나온 **벡터/스캔 판정** 결과를 이 파일 맨 아래에 붙여 둘 것. 없으면 B부터.
- 안전 원칙: 흐름 애니메이션은 전기적으로 맞아 보이므로 검증 전에는 화면에 "확인필요" 표시. 현장 확인 후 확정.

## 목표 (시범은 경로 1개만)
- 경로 1개 선택(예: SICAS 전원 N레벨 터미널(지침서 p.62 참고) → SV2602 → 채널). 사용자와 어떤 경로로 할지 먼저 확정.
- 도면 페이지 이미지 위에 투명 SVG 선을 얹고 stroke-dashoffset으로 붉은 흐름 애니메이션.

## 방식 (판정에 따라)
- **벡터:** PyMuPDF `get_drawings()`로 선 좌표 추출 → 연결된 선(net)을 자동 묶음 → 시작 단자/라벨에서 net 강조. 좌표는 0~1 비율로 JSON 저장.
- **스캔(이미지):** 뷰어에 "경로 그리기 도구"(클릭으로 점 찍고 JSON 저장/복사)를 만들어 사용자가 직접 그림. 토큰 소비 없음. 이미지를 눈으로 읽어 좌표 추정하는 방식은 부정확·고비용이라 피할 것.

## 데이터 형식 제안 (새 파일 `power-paths.json`)
```
{ "id": "...", "title": "...", "station": "SIN1", "verified": false,
  "steps": [ { "doc": "SICAS_HW_Design_SIN1", "page": 189, "points": [[0.12,0.30],[0.40,0.30]],
               "label": "설명", "continues": "p.190 F5" } ] }
```
- 여러 페이지: 단계 순서대로 재생, 한 페이지 끝나면 다음 페이지로 자동 전환, 연결점(`continues`)에 표시.
- 앱의 기존 **전원루틀 탭**은 개요로 유지하고 각 단계에서 도면으로 연결.

## 토큰 절약 원칙
- 무거운 처리는 스크립트로, 출력은 요약(개수·경로)만. 이미지는 확인할 부분만 잘라서 확인.
- 경로 하나씩, 사용자 확인 후 다음으로. 좌표 JSON은 다시 읽지 말 것.

## 끝낼 때
- 커밋(영문 메시지, Co-Authored-By 줄). push는 요청 시에만. 이 파일 맨 아래에 "세션 C 결과"(벡터/스캔별 소요·문제점, 확장 가능성) 추가.

## 세션 C 결과 (2026-09-29)
- 방식: 벡터(세션 B 판정). `claude/make_power_paths.py`(PyMuPDF get_drawings → T접점·교차점프 병합 net) → `power-paths.json`. HTML엔 `POWER_PATHS` 변수로 동일 내장(둘 다 같이 갱신).
- 시범 경로: SICAS_HW_Design_SIN1 **p.188**(S51 Level N 전원) 60V DC 인입 4가닥 → 채널 A/B/C용 단자블록. 4개 net 육안 검증(선 겹침 정확). 뷰어 툴바 ⚡ 버튼(해당 쪽에 경로 있을 때만 표시)으로 붉은 흐름 애니메이션 + "확인필요" 라벨. `verified:false`.
- **SV2602 구간은 못 이음:** SV2602는 EC/DSTT T52 캐비닛(p.224, Level A)에 있고 S51 N레벨(p.188)과 캐비닛이 다름. 도면상 N터미널→SV2602 직결 근거 없음(앱 전원흐름도는 T52 G단자→퓨즈→필터→SV2602). 이 구간은 현장/도면 확인 후 추가.
- 데이터 형식: 제안의 `points` 대신 `segments:[[x1,y1,x2,y2],...]`(net은 선 묶음이라 단일 폴리라인 불가). 흐름 방향은 세로=위, 가로=왼쪽으로 고정(인입→단자).
- 소요/문제: 선 12,491개 병합은 격자 버킷 필요(단순 O(n²)는 2분 초과, 지금 ~30초). 다단계 페이지 자동 전환/`continues`는 미구현(경로가 1쪽뿐).
- 확장: 다른 쪽·역은 스크립트의 PAGE/시작점(px)만 바꿔 재사용. 시작점 좌표 지정이 유일한 수작업.
