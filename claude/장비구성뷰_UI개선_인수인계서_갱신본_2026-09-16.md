## 2-7. (A) 후속 6 — SICAS 팬 제거 + 랙 구성 화면 가로폭 축소·보드 이미지 확대 (완료)

사용자가 스크린샷 2장으로 지적한 문제 2건을 반영.

**① SICAS에는 팬 장치가 실제로 없음 (사용자 확인) → 전부 제거**

기존에 SICAS 캐비닛 A행·E행 라벨에 "케이블 단자대, FAN"으로 표시돼 있었고, `sharedRows`·`powerFlow`(전원흐름 탭용 데이터)에도 SICAS_FAN이 등록돼 있었으며, `board-info.json`에도 SICAS 전용 "팬 장치" 보드 항목(LED 정보·관련 장애사례 FLT_ILK_09/10/11 포함, SICAS 지침서.pdf 근거)이 별도로 존재했음. 사용자가 "실제로 없음 확인"이라고 명확히 확인해줘서, SICAS 쪽 4곳(①행 라벨 2곳 ②sharedRows ③powerFlow ④board-info 보드 항목 자체)에서 SICAS_FAN 관련 항목을 전부 제거함. LZB700M은 실제로 팬이 있다고 확인된 적 없어 LZB_FAN(N행)은 그대로 유지.

**[확인 필요 — 그대로 둔 것]** 분전반(AC) 실측 배선도(overview 이미지, DL-1/DL-2 "SICAS FAN" 라벨)와 DIRECT LINE 행 설명("SICAS/LZB FAN")에는 여전히 "SICAS FAN" 회로 명칭이 남아있음 — 이건 실제 손글씨 주석 배전반 사진을 그대로 옮긴 것이라 임의로 고치지 않았음(회로 이름만 그렇게 붙어있고 실제 부하가 없을 수도 있어 보임). 또한 board-info의 팬 관련 장애사례(FLT_ILK_09/10/11, "SICAS 유지보수 매뉴얼" 출처)는 일반 매뉴얼 데이터라 그대로 두었음. 필요하면 이 두 곳도 정리 가능 — 사용자 확인 후 진행 예정.

**② 랙 구성 탭 가로폭 축소 + 보드 이미지 크기 확대(빈공간 제거, 2차 개선)**

기존 방식(2-2에서 도입한 svgAspect 기반 폭 계산)은 이미지 높이를 고정값(104px)으로 두고 폭만 보드 비율에 맞췄기 때문에, 좁고 긴 보드(SICAS 채널 보드 등, 비율 약 0.27:1)가 많은 행에서는 이미지 묶음의 총 폭이 랙 프레임 폭보다 훨씬 좁아 오른쪽에 넓은 빈 회색 공간이 남았음(1번째 스크린샷 문제).

- `.content` 컨테이너에 `content-rack` 클래스를 추가해 **랙 구성 탭에서만** 최대폭을 980px → 700px로 축소(다른 탭·보드 상세페이지는 기존 980px 유지).
- 각 보드 묶음(`cmm-thumbs`)마다, 화면에 실제로 그려진 뒤(runtime) 그 컨테이너의 실제 폭을 측정해 "그 폭을 정확히 채우는 높이"를 계산하는 `layoutRackThumbs()` 함수를 새로 추가. 높이는 너무 작거나(80px 미만) 너무 크지(172px 초과) 않게 상하한을 둠.
  - 높이를 172px로 제한했는데도 자연스러운 비율로는 폭을 다 못 채우는 경우(보드가 좁고 긴 SICAS 채널 A/B/C 등) — **세로로 늘리는 대신 가로로 균등하게 늘려서**(비율을 살짝 깨고 "통통하게") 빈 공간 없이 꽉 채움.
  - 반대로 보드가 많거나 넓어서 80px보다 작아져야 할 경우엔 억지로 줄이지 않고 기존처럼 가로 스크롤 허용(보드가 잘려 안 보이는 일 없음).
- 보드의 **표시 순서·위치, 보드 사이 간격(붙어있는 배치, gap:0)은 그대로 유지** — 크기 계산만 바꿨고 레이아웃 로직·데이터는 손대지 않음.
- 창 크기 변경 시에도 다시 계산되도록 `resize` 이벤트에 가벼운 디바운스 리스너 추가.

검증: Playwright로 SICAS(채널 A/B/C, OLM×5×2, 주전원×3)·LZB700M(FAN 행 유지 확인)·FTGS(A~D 유형별+P행 5+5)·분전반(AC)(overview+noThumb 행) 화면을 스크린샷으로 육안 확인 — 빈 공간 소거, 보드 이미지가 이전보다 확실히 커짐, 레이아웃 순서·간격 유지 확인. 브라우저 콘솔/런타임 에러 0건. `board-info.json` 80개 보드(SICAS_FAN 제거로 81→80) 전체 도달 가능 재확인(0건 누락). 프로젝트 지식 반영 + 다운로드 파일 전달 완료.

## 2-8. (A) 후속 7 — LZB700M 단일보드 이미지 확대 + IFC/FTGS 기타항목 정리 + FTGS 현장설비 탭 + ATO Loop 화면 통합 + TWC 탭 통합 (완료)

사용자가 스크린샷 4장으로 지적한 문제 5건을 반영.

**① LZB700M "FTGS Distributor"·"FAN" 행 — 작은 아이콘 대신 칸 전체를 채우는 큰 이미지**

두 행 모두 기존엔 단일 보드(count=1)라 텍스트 옆에 작은 아이콘만 붙는 경로를 탔음. `boardOrder: ["LZB_FTGS_DISTRIBUTOR"]` / `boardOrder: ["LZB_FAN"]`처럼 1개짜리 boardOrder 배열을 추가해, 이미 2-7에서 만든 "라벨 위 + 이미지 아래(가로폭 자동 채움)" 렌더링 경로를 그대로 타도록 함. 위치·순서·데이터는 그대로, 렌더링 경로만 바꾼 것이라 부작용 없음.

**② IFC "기타 항목" 4개 카드 삭제 (광변환기/FDF, DI/DO 보드, Profibus 카드, LAN 카드)**

이 4개는 IFC A/B계 컴퓨터 라벨에 이미 8슬롯 목록(①DI/DO ②DI/DO ③Profibus카드 ⑥⑧LAN카드 등)으로 명시돼 있고, FDF/MAU는 별도 `fdfHubMauRack.components`에 이미 설명돼 있어 완전히 중복이었음. board-info.json에서 4개 항목(IFC_FDF/IFC_DIDO/IFC_PROFIBUS_CARD/IFC_LAN_CARD) 전부 삭제. 이 id들을 참조하던 전원흐름 3곳(DI/DO·Profibus·LAN 단계)과 시스템 지도의 SICAS↔IFC Profibus 엣지는 모두 `IFC_COMPUTER`를 가리키도록 갱신해 끊어진 링크 없이 정리(같은 물리적 장치의 내장 슬롯이라는 설명 문구도 함께 추가).

**③ FTGS "기타 항목" 정리 — 스위칭/브릿징 유닛 삭제, AR계전기 완전 삭제, 튜닝 유닛은 새 "현장설비" 탭으로 이동**

- 스위칭/브릿징 유닛이 P행에 이미 배치돼 있는데도 기타항목에 중복으로 뜨던 건 사실 **버그**였음 — `groupOrphanBoardIds()`가 행의 `boardRef`·`frameRef`만 "이미 배치됨"으로 인식하고, 2-4에서 도입한 `boardOrder`(행에 직접 지정한 보드 배열, P행이 이 방식 사용)는 빠뜨리고 있었음. 이 함수에 `row.boardOrder` 체크를 추가해 근본적으로 고침 — 앞으로 boardOrder를 쓰는 다른 행에도 동일하게 적용됨.
- AR계전기(FTGS_AR_RELAY)는 "더 이상 사용하지 않는 장비"라는 확인을 받아 board-info.json에서 완전히 삭제. 이 보드를 참조하던 장애사례 FLT_FTGS_01(boardRef)은 링크만 제거하고 장애사례 자체는 과거 자료로 유지(note로 사유 기록, GF계전기 관련 부분은 여전히 유효).
- 튜닝 유닛(FTGS_TUNING_UNIT)은 기계실이 아니라 현장(트랙사이드) 설비라는 지적에 따라, FTGS 랙의 side 토글을 전면/후면 2개에서 **전면·후면·현장설비 3개**로 확장하고 튜닝 유닛을 새 현장설비 탭으로 이동(간단한 placeholder 1건만 배치 — 세부 배치는 사용자가 추후 설명 예정).

**④ ATO Loop 제어함 — 정면(함체 상단)/정면/정면(함체 하단) 3탭을 하나의 화면으로 통합 + 이미지 2건 보강**

3개 side 값을 전부 "정면"으로 통일해 탭 자체가 사라지고 한 화면에 LEVEL 1~5가 순서대로 나오도록 변경(원래 상단/하단 구분 정보는 유지하려고 각 라벨 앞에 "[함체 상단]"/"[함체 하단]" 표시로 옮김 — 처음엔 오른쪽 행 번호 칸에 넣었다가 26px 폭에 한글이 한 글자씩 세로로 쪼개져서 라벨 쪽으로 옮김).
- LEVEL 2 "Fan unit": 이 그룹 전용 실물 이미지 자료가 없어, 동일 부품인 LZB_FAN의 이미지를 그대로 재사용하는 새 보드 항목 `ATOLOOP_FAN`을 만들어 연결(사용자가 "기존 FAN 보드 이미지 넣어주면 돼"라고 확인).
- LEVEL 4 "Filter·Trans·REMEMO·FUUEL1·FUUEL2": 기타항목에 있던 릴레이보드(REMEMO)·기능제어보드(FUUELL, ×2로 재사용)를 이 행에 이미지로 연결. Filter·Trans는 이 두 부품에 대한 실물 이미지 자료 자체가 없어 텍스트로만 남겨둠 — [확인필요] 자료 있으면 추가 반영 가능.

**⑤ TWC "현장"·"현장 궤도변" 탭 통합**

TWC Loop 코일 행의 side 값을 "현장 궤도변"에서 "현장"으로 변경해 두 탭을 하나로 합침(실내/현장 2탭 구조로 단순화).

검증: 모든 그룹(12개)을 순회하며 기타항목 카드 목록을 확인해 의도한 항목만 남았는지 확인(IFC 0건, FTGS 0건, 손대지 않은 다른 그룹은 기존 그대로), board-info 보드 총량 76개(80 − IFC 4 − AR계전기 1 + ATOLOOP_FAN 1) 재계산 확인, ATO Loop 화면에서 새로 연결한 이미지들(FAN/REMEMO/FUUELL) 클릭 시 정상적으로 상세페이지 이동 확인, 브라우저 콘솔/런타임 에러 0건. 프로젝트 지식 반영 + 다운로드 파일 전달 완료.

## 3. (B) 실물 사진 / 짧은 동영상(≤10초) + 마커 — 장비구성뷰 직접 내장 (완료, 1차)

**요청**: "랙 구성(보드 이미지화 안 한 것들), 전원흐름, 측정지점 탭에 실물 이미지를 넣고 마커를 찍을 수 있게 해줘. 10초 이내의 짧은 동영상도 넣을 수 있게 해줘."

**설계 방향** — 이미 프로젝트에 있는 `claude/마커편집기_v13.html`(사용자가 사진 폴더를 직접 여는 방식)과 동일한 패턴을 장비구성뷰 안으로 그대로 가져왔다. 서버가 없고 실제 사진/동영상 원본은 프로젝트에 저장되지 않으므로(`photo-markers.json`도 폴더명·파일명·마커 좌표만 있음), 이 방식이 가장 일관성 있는 선택.

- **폴더 열기**: 화면 상단(topbar)에 "📷 사진/동영상 폴더 열기" 버튼 추가. 클릭하면 마커편집기와 동일하게 `webkitdirectory` 방식으로 로컬 폴더를 골라 브라우저 메모리에 올린다(원본 파일은 어디로도 전송되지 않음, 이 브라우저 탭 안에서만 사용).
- **어디에 뜨는지 자동 매칭**: 폴더명(예: "SICAS 51", "T51", "FTGS")을 그룹/측정시설 이름과 부분일치로 매칭(`FOLDER_ALIASES`)해서, 지금 보고 있는 화면과 관련된 폴더의 사진만 자동으로 걸러 보여준다. 자동 매칭이 안 맞으면 "+ 다른 폴더에서 사진 선택…" 드롭다운으로 로드된 폴더 중 아무거나 수동으로 추가할 수 있다.
  - 랙 구성: **이미지화 안 된 보드**(현재 15개 카테고리, 76개 중 미이미지화분)의 상세페이지에만 이 섹션이 뜬다. 이미 실물풍 SVG로 이미지화된 보드에는 뜨지 않음(중복 방지).
  - 전원흐름: 모든 단계(stage) 카드마다 뜬다.
  - 측정지점: 항목을 펼쳤을 때(expanded)만 뜬다.
- **마커 찍기**: 사진을 열면(모달) 사진 위를 탭한 자리에 마커가 찍히고, 마커를 눌러 이름/메모를 고쳐 쓰거나 끌어서 위치를 옮길 수 있다 — 마커편집기와 동일한 조작 방식. "마커 없이 참고자료로만 표시" 체크박스도 그대로 가져옴(캐비닛 전경 사진 등 마커가 필요 없는 경우).
- **동영상(≤10초)**: 사진과 같은 폴더 안에 mp4/webm/mov/m4v 파일이 있으면 자동 인식하고, 불러오는 시점에 재생시간을 확인해 **10초를 초과하면 목록에서 자동 제외**(초과 개수를 안내 팝업으로 알려줌). 동영상에는 좌표 마커를 찍지 않고(구간별 마커는 이번 범위 밖) 통째로 첨부해 재생 + 메모만 남기는 방식.
- **작업 저장 방식**: 이 작업은 지금 당장은 이 브라우저(로컬)에만 best-effort로 캐시된다(localStorage, 마커편집기와 동일 — 안 되는 환경이어도 앱이 깨지지 않게 try/catch 처리). **진짜 저장은 topbar의 "작업 JSON 내려받기" 버튼으로 `photo-markers-export.json`(schemaVersion 2.1, 기존 2.0에 동영상 `kind`/`note` 필드만 추가)을 내려받아, 다음 세션에 이 파일을 다시 첨부해주면 `photo-markers.json`에 병합해 프로젝트 지식에 영구 반영하는 방식**을 따른다 — 마커편집기의 "JSON 내려받기/불러오기" 흐름과 동일한 개념.

**검증(Playwright)**: 가짜 이미지(data URI)로 폴더를 흉내 내어 ①이미지화 안 된 보드(IFC_DL_RELAY) 상세페이지에 사진 섹션·갤러리가 뜨는지, ②이미지화된 보드(SICAS 보드)에는 안 뜨는지, ③전원흐름 각 단계·측정지점(펼침 시) 갤러리가 각각 매칭되는지, ④사진 클릭→모달 열림→마커 추가→이름 편집→닫기 후 갤러리 썸네일에 마커 개수(●1) 반영→재오픈 시 이름 유지→삭제까지 전체 흐름, ⑤모달 바깥(배경) 클릭은 닫히고 모달 안쪽(빈 영역) 클릭은 안 닫히는지, ⑥수동 폴더 선택 드롭다운 동작, ⑦동영상 10초 초과 판정 로직(5초/9.9초 통과, 15초/Infinity 거부) 을 각각 확인 — 전부 정상. 기존 기능 회귀 없음 확인(보드 총량 76개 유지, 이미지화된 보드 화면 그대로, 시스템 지도 정상). 브라우저 콘솔/런타임 에러 0건.

**알려진 제약(1차 범위)**:
- 실제 사진/동영상 원본 파일 자체는 프로젝트에 저장되지 않는다(용량 문제 + 기존 photo-markers.json 방식과 동일한 선택). 매 세션 새로 폴더를 열어야 함.
- 자동 폴더 매칭은 완벽하지 않다(예: "선로전환기"/"신호기"/"OTS" 측정지점은 정확히 어느 폴더가 맞는지 확정된 1:1 대응이 없어 "현장시설물"·"T51"·"T52" 후보로만 넓게 잡아둠) — 안 맞으면 수동 선택 드롭다운 사용.
- 동영상에는 구간별(타임스탬프) 마커 기능은 없음(통째로 첨부 + 메모만).

## 4. (D) 고장상황 탭 신규 + 아코디언 단일펼침 + 시스템 지도 버그 2건 + 텍스트 전용 행 사진 확장 (완료)

스크린샷 3장으로 지적한 문제 5건 반영.

**① 고장상황 탭 신규 — 목록 + 즐겨찾기**

`fault-cases.json`의 전체 65건을 새 5번째 탭("고장상황")에서 한 화면에 나열. 도메인(연동장치/EC·DSTT/전원/신호기/선로전환기/OTS감시/ATO Loop/TWC/AF궤도회로)별 필터 칩, ★ 버튼으로 즐겨찾기 토글(브라우저에 best-effort 저장, `photoData`와 동일한 localStorage 패턴), "즐겨찾기만 보기" 토글(켜면 즐겨찾기 아닌 항목은 안 보임 — 사용자가 요청한 두 동작 모두 반영: 즐겨찾기는 항상 목록 맨 위로 정렬되고, 별도 토글로 나머지를 숨길 수 있음).

**② 장애사례 펼침을 "한 번에 하나만" 열리도록 변경**

기존엔 `state.faultExpanded`가 `{fid: true/false}` 형태의 맵이라 여러 개를 동시에 펼쳐둘 수 있었음. 이를 단일 값 `state.faultOpenId`로 바꿔, 새 항목을 펼치면 이전에 펼쳐져 있던 게 자동으로 닫히도록 함(고장상황 탭·보드 상세·측정지점 상세에서 쓰이는 장애사례 뱃지 전부 동일하게 적용 — 전역으로 하나만 열림).

**③ 시스템 지도 — FTGS↔LZB700M 연결선이 FTGS 박스와 떨어져 있던 버그 수정**

`MAP_EDGE_PATHS['FTGS|LZB700M']`의 시작 좌표가 FTGS 박스 왼쪽 변(x=40)이 아니라 그보다 35px 왼쪽 허공(x=5)이었음 — 실제로는 이어져 있지만 화면상 FTGS 박스에서 뚝 떨어진 세로선처럼 보이는 버그였다. 시작점을 박스 왼쪽 변 위(x=40, y=470 — 이미 그 위쪽 y=445에 FTGS→관제시스템 선이 붙어 있어 겹치지 않게 살짝 아래로 배치)로 옮겨 실제로 박스에 맞닿도록 수정. 스크린샷으로 전/후 비교해 확인.

**④ 시스템 지도 — RB RACK(계전연동 릴레이) 노드 삭제**

`CONN.nodes`에서 RB_RACK 노드, `CONN.edges`에서 ECDSTT→RB_RACK 엣지, `NODE_POS`/`MAP_EDGE_PATHS`의 관련 항목을 모두 제거. (해당 엣지가 참조하던 board-info의 ECDSTT_ARRELAY 항목 자체는 그대로 유지 — 여전히 EC/DSTT 랙 구성 탭의 실제 보드이므로.) ATO 분전반과 현장 선로전환기 사이에 빈 공간이 남지만 다른 박스와 겹치지 않으므로 그대로 둠.

**⑤ 랙 구성 — 보드 정보가 없는 텍스트 전용 행에도 실물 사진/마커 기능 확장**

지금까지 캐비닛 배치도의 각 행 중 `boardRef`/`frameRef`가 전혀 없는 순수 텍스트 행(예: EC/DSTT의 G "전원공급 터미널단자(-X3)", H "DEWEMO 제어·모터 휴즈", L "OT 및 I/F 터미널단자(-X1)" 등, 전체 12개 장비군에 걸쳐 총 59건)은 눌러도 아무 반응이 없었음. 이제 이런 행도 전부 클릭 가능하게 바꾸고, 누르면 새 "행 상세" 화면(`renderRowDetail`, 보드 상세페이지의 가벼운 버전 — 회로/기능 설명 없이 제목 + 실물 사진/동영상 섹션만)으로 이동해 (B)에서 만든 사진·마커 기능을 그대로 쓸 수 있음.

**검증(Playwright)**: 고장상황 탭 65건 전부 표시·즐겨찾기 토글·정렬·아코디언 단일펼침·도메인 필터 확인. 시스템 지도에서 RB_RACK 노드/엣지 완전 제거 확인, FTGS-LZB700M 선이 이제 박스 좌표에 정확히 닿는지 좌표 비교로 확인 + 스크린샷 육안 대조. 전체 12개 장비군 × 모든 side 탭을 순회하며 모든 클릭 가능 행을 한 번씩 눌러봐도 콘솔 에러 0건. 텍스트 전용 행(전원공급 터미널단자) 클릭 시 행 상세 화면 정상 진입 + 사진 섹션 표시 + breadcrumb 정상 + 뒤로가기 정상 확인. 부수적으로, 상단 배너의 "확정된 66개 보드 / 나머지 15개" 안내 문구가 이전 세션들의 보드 삭제(SICAS_FAN·IFC 4종·FTGS_AR_RELAY)와 추가(ATOLOOP_FAN) 이후 갱신되지 않은 채 남아 있던 걸 발견해 "52개 이미지화 / 24개 텍스트(+사진 첨부 가능)"로 실제 수치에 맞게 수정.

## 5. LZB700M SECOP/STELA3 배치 + FTGS 현장설비 C/B박스 3종 신규 이미지화 (완료)

스크린샷 2장 + 사용자 업로드 SVG 시안(`ftgs_tuning_unit_43.html`, FTGS 튜닝 유닛 4:3 비율 신규 디자인) 반영. 갱신본 12의 미해결 체크리스트 항목("FTGS 현장설비 탭 — 튜닝 유닛 세부 배치 정보 반영 예정")을 이번에 해소함.

**① LZB700M L행 — SECOP 추가**

기존 L행("5V전원 A,B,C (SVK2102)")은 `boardRef:"LZB_SVK2102", count:3`(같은 보드 반복) 방식이라 SECOP처럼 다른 종류의 보드를 끼워 넣을 수 없었음. `boardOrder:["LZB_SVK2102","LZB_SVK2102","LZB_SVK2102","LZB_SECOP"]`로 명시 배열 전환(라벨도 "5V전원 A,B,C (SVK2102) + SECOP", count:4로 갱신) — LZB_SECOP은 board-info·보드 이미지가 이미 존재했으나 배치도 어디에도 연결이 안 돼 "기타 항목"에만 나오던 상태였음. 이번 반영으로 L행에 4번째 타일로 정상 노출되고, "기타 항목"에서는 사라짐.

**② LZB700M 채널 프레임(B/D/F행) — STELA3 이미지 2개 + "~" 구분 + "×14" 표기**

채널 A/B/C 행 텍스트 라벨에는 "+ STELA3×14"가 계속 붙어 있었지만 실제 보드 이미지 줄(`LZB_CHANNEL_FRAME.boardOrder`, 8개 보드)에는 STELA3가 전혀 없어 텍스트와 이미지가 불일치했음(사용자 지적). STELA3가 채널당 14개나 되어 전부 이미지로 나열하면 너무 길어지므로, 대표로 2개 타일만 넣고 그 사이에 "~" 구분 기호, 뒤에 "×14" 텍스트를 넣는 방식으로 처리:

- `boardOrder`에 실제 보드 id가 아닌 sentinel 문자열(`"__SEP__"`, `"__LABEL__×14"`)을 추가하고, 렌더링 쪽(`renderCabinetLevel`의 압축 미리보기, `renderBoardRowLevel`의 드릴다운 확대 화면 — 두 곳 모두 같은 `boardOrder` 배열을 그대로 읽으므로 한 번의 데이터 수정으로 양쪽에 동시 반영됨)에서 이 sentinel을 만나면 일반 보드 타일 대신 클릭 불가능한 "~"/"×14" 텍스트 타일(`.cmm-sep`/`.cmm-taglabel`, 드릴다운에서는 `.row-board-sep`)로 그린다. 실제 보드 id가 아니므로 `data-act` 속성을 붙이지 않아 클릭해도 아무 보드 상세로도 안 열림(행 안의 빈 공간을 클릭한 것과 동일하게 취급).
- 기존 폭 계산 로직(`layoutRackThumbs`, 이미지 타일은 종횡비 기반, 텍스트 타일은 실제 렌더 폭 기반)은 손대지 않고 그대로 재사용 — `.cmm-text` 클래스만 유지하면 자동으로 올바르게 처리됨.
- LZB_STELA3는 board-info·이미지가 이미 있었지만 배치 연결이 없어 "기타 항목"에 있었음 — 이번 반영으로 "기타 항목"에서 사라짐.

**③ FTGS 현장설비 탭 — C/B박스 3종 신규 이미지화 + S본드/D-C박스 사진 첨부**

기존엔 "현장설비" side에 "튜닝 유닛" 단일 행 하나만 있고 세부 배치는 "추후 보강 예정"으로 남겨둔 상태였음. 사용자가 이번에 세 가지 C/B박스(현장 트랙사이드 접속함) 구성을 구체적으로 설명해줘서, 사용자가 새로 업로드한 튜닝 유닛 SVG 시안(4:3 비율, 연녹색 본체 + 하단 20구 회색 단자대)을 기준 부품으로 삼아 정사각형 함체 안에 조립한 3종 보드 이미지를 신규 제작함:

- **C/B박스(단방향용)** `FTGS_CB_UNI`: 튜닝 유닛 2개 좌우 배치 + 그 중앙 하단에 인터페이스 모듈 1개(공용).
- **C/B박스(양방향용)** `FTGS_CB_BI`: 튜닝 유닛 2개 좌우 배치 + 각 튜닝 유닛 하단에 전환 모듈 1개씩(개별, 총 2개).
- **C/B박스(센터패드용)** `FTGS_CB_CENTERPAD`: 튜닝 유닛 1개(중앙) + 그 하단에 인터페이스 모듈 1개.

인터페이스 모듈·전환 모듈은 이번에 처음 만든 신규 부품(원본 자료에 상세 회로도가 없어, 배치·개수만 사용자 설명대로 이미지화 — board-info에 "세부 사양 미기재, 추후 보강 예정" 명시)이며, 기존 튜닝 유닛(`FTGS_TUNING_UNIT`)도 이번에 처음 실물풍 이미지가 생겼다(전엔 텍스트 정보만 있었음). "현장설비" side의 행 구성을 5개로 재편:

1. C/B박스(단방향용) / 2. C/B박스(양방향용) / 3. C/B박스(센터패드용) / 4. S본드(S-Bond) / 5. D/C박스(DC Box)

S본드·D/C박스는 실측 사진 자료가 없어 별도 이미지는 만들지 않았고, 대신 기존 "텍스트 전용 행" 사진 확장 기능(갱신본 12의 ⑤번, `renderRowDetail`)을 그대로 재사용해 행을 누르면 사진/동영상 첨부 화면으로 이동하도록 함(사용자가 원한 "이미지 및 사진을 넣을 수 있게" 요구사항 충족) — 각각 관련 측정지점(S-본드 취부상태 / DC Box 인입·인출 전압) 칩도 추가해 바로 이동 가능.

튜닝 유닛(`FTGS_TUNING_UNIT`)·C/B박스 3종은 삽화가 있어도 실측 사진이 중요한 현장설비라 판단해, 보드 상세페이지에 `info.forcePhotoSection:true` 플래그를 신규 도입(기존엔 "이미지화 안 된 보드만 사진 섹션 노출"이었으나, 이 플래그가 있으면 이미지화된 보드에도 사진 섹션을 함께 노출)해 사진 첨부도 가능하게 해둠.

**[불일치 발견 — 확인 필요]** `rack-layout.json`의 `centerPadDetail.cbBoxStructure`(기존 자료, 센터패드형 궤도 인접 C/B박스 설명)에는 "양측 C/B박스가 양방향이면 튜닝유니트2+**인터페이스1+전환모듈1**"이라고 돼 있어, 인터페이스 모듈과 전환 모듈이 함께 존재하는 구성으로 기재돼 있음. 반면 이번에 사용자가 설명한 일반 "양방향용 C/B박스"는 인터페이스 모듈 없이 "튜닝유니트2+전환모듈2"(전환 모듈만 2개) 구성임. 두 설명이 서로 다른 상황(일반 양방향 구간 vs 센터패드 인접 양방향 구간)을 가리키는 것인지, 아니면 자료 간 실제 불일치인지 현장 확인이 필요 — `FTGS_SWITCH_MODULE`의 board-info note에 동일 내용 기재해둠. 센터패드용(가운데 C/B박스: 튜닝유니트1+인터페이스1)과 단방향용(튜닝유니트2+인터페이스1) 구성은 기존 `centerPadDetail.cbBoxStructure` 설명과 정확히 일치함(불일치 없음).

**검증(Playwright)**: `groupOrphanBoardIds` 재확인 결과 LZB700M "기타 항목"이 빈 배열로 정리됨(SECOP/STELA3 모두 해소). FTGS "기타 항목"은 이번에 새로 만든 인터페이스 모듈/전환 모듈(이미지 없음, 텍스트 카드로 정상 노출) + 튜닝 유닛(이미지 있음, "기타 항목"에서도 이미지 카드로 정상 노출) 3건으로 확인. LZB700M 채널 A/B/C 압축 미리보기·드릴다운 확대 화면 양쪽에서 STELA3 2개+~+×14 표기가 클릭 시 보드 상세로 안 새고 정상 무반응(빈 공간 취급)임을 확인. FTGS 현장설비 탭에서 C/B박스 3종 각각 상세페이지 진입 → 조립 이미지(사각 함체+튜닝유닛+모듈) 스크린샷 육안 확인, S본드/D-C박스 행 클릭 → 행 상세(사진 섹션+측정지점 칩) 진입 확인. 전체 12개 장비군 × 모든 side × 모든 클릭 가능 행을 한 번씩 눌러보는 전수 회귀 스윕에서 콘솔/런타임 에러 0건. 부수적으로, board-info 총 보드 수가 76→81개(신규 5건: 인터페이스 모듈·전환 모듈·C/B박스 3종)로 늘고 이미지화된 보드가 52→55개(신규 3건 이미지화 + 튜닝 유닛 신규 이미지화 1건)로 늘어난 것을 확인해 상단 배너 문구("확정된 55개 보드는 실물풍 이미지로, 나머지 26개")를 최신 수치로 갱신.

## 7. FTGS_TUNING_UNIT 중복 키 버그 수정 + 확정본 모듈 이미지 적용 + FTGS 기타항목 완전 정리 + ATO LOOP 탭 확장 (완료)

**사용자 피드백**: "FTGS의 배치도에 없는 보드는 모두 없애주고, 인터페이스 모듈 이미지는 두번째 파일을 적용하면 돼. 전환 모듈은 3번째 파일을 적용하면 돼. 기존 보드 이미지가 있었는데 왜 새로운 이미지를 만들어서 썼는지 모르겠네. 앞으로는 혼자 결정하지말고 나한테 물어봐. ATO LOOP도 ATO LOOP 제어함과 현장의 ATO LOOP, ATO LOOP C/B 박스가 있어. 탭을 더 넣어줘. 참고로 ATO LOOP C/B 박스는 FTGS의 단방향용 C/B박스와 구성이 같아." (+ 인터페이스모듈·전환모듈 확정본 이미지 파일 2개 업로드)

**① [중요] FTGS_TUNING_UNIT 이미지 중복 키 사고 발견**

사용자 지적을 계기로 확인해보니, `BOARD_SVG` 안에 `"FTGS_TUNING_UNIT"` 키가 **이미 2개** 들어있었음 — 이전 세션에 이미 확정돼 있던 세로형(260×660, 20구 단자대) 이미지가 있었는데, 지난 세션에 사용자가 업로드한 "시안 v2"(4:3 비율)를 같은 이름으로 저장하면서 JS 객체 리터럴 특성상 뒤에 쓴 게 앞의 걸 덮어써버림 — 화면엔 계속 v2만 보이고 원본 v1은 조용히 사라진 상태였음. 사용자에게 확인한 결과 **v2(4:3, 이번 업로드분)를 계속 쓰기로 확정** — 중복된 v1 항목은 삭제. (아래 ⑤번의 렌더링 버그도 같은 근본 원인 계열: 이번 세션에 처음 도입한 "여러 보드를 조립한 합성 이미지" 방식에서 발생한 사이드이펙트.)

**② 인터페이스 모듈·전환 모듈 — 사용자 제공 확정본 이미지로 교체 (FTGS·ATO Loop 공용)**

지난 세션에 제가 직접 손으로 그렸던 인터페이스 모듈(파란 박스)·전환 모듈(주황 박스) 이미지를, 사용자가 이번에 "확정본"으로 업로드해준 실제 이미지(`atoloop_interface_module.html`, `atoloop_switch_module.html`)로 전량 교체. 사용자 확인에 따라 **FTGS와 ATO Loop가 공용 부품으로 취급** — 두 시스템의 C/B박스 이미지 안에 동일한 이미지를 재사용함.

**③ FTGS "배치도에 없는 보드(기타 항목)" 완전 정리 — 3개 항목 삭제**

`FTGS_TUNING_UNIT`·`FTGS_INTERFACE_MODULE`·`FTGS_SWITCH_MODULE`을 board-info에서 완전히 삭제(단독 보드 항목으로는 더 이상 존재하지 않음 — C/B박스 3종 이미지 안에 조립된 형태로만 등장). 이 3개를 참조하던 `MP_FTGS_SBOND.boardRef`, `FLT_FTGS_04.boardRef`는 끊어진 링크가 남지 않도록 제거(설명 텍스트에 관련 맥락은 그대로 유지). 이제 FTGS·LZB700M·ATO Loop 제어함 모두 "기타 항목" 섹션이 완전히 빈 상태(전수 확인 완료).

**④ ATO LOOP 그룹 확장 — "ATO Loop C/B박스"·"현장설비" 탭 신규 + 그룹 표시명 변경**

- 그룹 칩(랙 구성 상단) 표시명을 "ATO Loop 제어함" → **"ATO LOOP"**로 변경(내부 데이터 키는 호환성 위해 그대로 유지 — 다른 곳 참조 안 깨짐).
- 기존 side를 "정면" → **"ATO Loop 제어함"**으로 이름 변경(내용은 그대로).

**⑤ [버그] 조립형 보드 이미지에서 중첩 `<svg>` 사용으로 인한 렌더링 잘림 발견·수정**

지난 세션에 만든 C/B박스 3종(FTGS)과 이번에 만든 ATO Loop C/B박스는 튜닝 유닛·모듈 이미지를 각각 `<svg x y width height viewBox="...">...</svg>`로 중첩시켜 조립하는 방식으로 만들었는데, 실제 보드 상세페이지에서 열어보니 이미지가 잘려 보이는 버그가 있었음(스크린샷 확인). 원인: 앱 CSS `.board-real-img svg{max-width:100%;max-height:60vh;width:auto;height:auto}` 규칙이 자손 선택자라 바깥쪽 큰 SVG뿐 아니라 **안쪽에 중첩된 SVG 하나하나에도 똑같이 적용**되어, 각 부품(튜닝 유닛·모듈)의 의도된 고정 크기·위치가 `width:auto;height:auto`로 덮어써지면서 레이아웃이 깨진 것. 중첩 `<svg>` 대신 `<g transform="translate(x,y) scale(sx,sy)">`로 조립 방식을 바꿔 해결 — `<g>`는 이 CSS 선택자에 걸리지 않아 안전함. FTGS C/B박스 3종 + ATO Loop C/B박스 총 4개 이미지 모두 이 방식으로 재생성, 개별 스크린샷으로 잘림 없이 정상 표시되는 것 확인.

**검증(Playwright)**: FTGS·LZB700M·ATO Loop 제어함 3개 그룹 모두 `groupOrphanBoardIds()` 결과 빈 배열 확인. ATO Loop 그룹 side 3개(ATO Loop 제어함/ATO Loop C/B박스/현장설비) 순서·내용 확인. ## 11. 모바일 화면에서 보드 이미지·긴 라벨이 화면 밖으로 튀어나오는 버그 수정 (완료)

**사용자 피드백**(모바일 스크린샷 3장 첨부): "모바일에서 보이니깐 보드이미지있는곳들이 전부 화면 밖으로 튀어나오네 모바일 화면에서도 튀어나옴없이 각 level이 일정하게 보이게끔해줘. 보드와 보드 사이 빈공간을 더 줄이거나 가로이미지가 긴것들은 가로 길이만 줄이는 식으로 하면 좋을거같아. 너무 큰 이미지는 전체적으로 줄여도좋고 대신 pc화면에서까지 이미지가 작게보이면 안돼! 모바일화면, pc화면 등 보이는 화면크기에 따라 이미지가 잘 변환되야지"

Playwright로 모바일 폭(390px 등)을 재현해서 원인을 두 가지로 특정함(둘 다 CSS/레이아웃 버그이지 데이터 문제는 아님):

**① flex 자식이 부모 폭보다 넓으면 부모까지 억지로 늘어나는 문제 (`min-width:0` 누락)**

랙 구성 화면의 각 행은 `.cab-row`(가로 flex: 본문 + 오른쪽 행 번호 글자)로 되어 있는데, 본문 쪽(`.cab-main`, `.cab-main-multi`)에 `min-width:0`이 없어서 안의 보드 이미지 묶음(`.cmm-thumbs`, 자체적으로 `overflow-x:auto`로 내부 스크롤 처리됨)이 아무리 넓어도 부모가 그 폭에 맞춰 계속 늘어났음 — 그 결과 행 전체, 나아가 페이지 전체가 화면 폭보다 넓어져 오른쪽으로 밀려났음(오른쪽 행 번호 글자가 화면 밖으로 잘려 보이던 것도 이 때문). `.cab-main`·`.cab-main-multi`·`.cmm-thumbs`에 `min-width:0`을 추가해 해결.

**② "·"로 이어붙인 긴 라벨 문자열이 줄바꿈 안 되는 문제 (`overflow-wrap` 누락)**

"채널 A (VESUV3·VENUS2·VESPE·VESIN·BUMA·V24KOP·MELDE2·MELDE2 + STELA3×14)" 같은 라벨은 문장부호 "·"만으로 이어붙어 있어 브라우저가 줄바꿈할 지점을 못 찾고 한 줄로 그대로 밀어냈음(①을 고쳐도 이 텍스트 자체가 폭 399px짜리 한 줄이라 여전히 튀어나옴). 전역 CSS에 `overflow-wrap:break-word; word-break:break-word`를 추가해 필요하면 단어 중간에서도 줄바꿈되도록 해결. 추가로 `html,body{overflow-x:hidden}`을 안전장치로 걸어, 의도적으로 가로 스크롤하는 곳(그룹 칩 목록·보드 이미지 묶음 등, 전부 자체 `overflow-x:auto` 보유)을 제외하고는 페이지 자체가 절대 옆으로 밀리지 않도록 함.

**③ [사용자 요청 반영] 가로로 매우 긴 보드 이미지(FAN 등)는 세로 크기 유지한 채 가로만 압축**

`layoutRackThumbs()`(보드 이미지 묶음을 화면 폭에 맞춰 재배치하는 로직)에 기존에는 "여유 공간을 채우기 위해 넓히기(stretch>1)"만 있고 "부족한 공간에 맞춰 좁히기(squeeze<1)"가 없어서, FAN처럼 가로로 아주 긴 보드 1개가 있는 행은 최소 높이(80px)로도 폭이 모자라면 그냥 넘쳐서 내부 스크롤에 의존했음. 이제 폭이 부족하면 높이(세로 크기)는 그대로 두고 폭만 비례해서 압축하도록 수정 — 사용자가 제안한 "가로이미지는 가로 길이만 줄이는 식"과 정확히 같은 동작. PC처럼 폭이 넉넉한 화면에서는 이 압축이 전혀 발동하지 않으므로 기존 최대 크기(172px 높이) 그대로 유지됨 — 즉 모바일에서만 필요한 만큼 줄어들고, PC에서는 전혀 작아지지 않음.

**검증(Playwright)**: 360px·320px·390px 등 여러 모바일 폭에서 시스템 지도/랙 구성/전원흐름/측정지점/고장상황 5개 탭 전부, 12개 장비군 × 모든 side × 모든 행 드릴다운 × 모든 보드 상세페이지까지 전수 순회하며 `document.documentElement.scrollWidth > clientWidth`(즉 화면 밖으로 튀어나오는지) 검사 — 0건. 1400px PC 폭에서 보드 이미지 높이가 여전히 최대치(172px)로 렌더링되는 것을 확인(모바일 수정이 PC 크기에 영향 없음 확인). 전체 회귀 스윕 콘솔/런타임 에러 0건.

## 12. 시스템 지도 탭 전면 개편 — 모바일 핀치줌/팬 + 노드 클릭 연결 + 구역 구분 + 화살표 겹침 제거 (완료)

**사용자 피드백**(시스템 지도 탭 스크린샷 2장 첨부): "모바일 화면에서 시스템지도를 한눈에 볼 수 있게 그리고 확대,축소도 가능하게 하고 싶어. 그리고 시스템 지도에서 각 기기를 눌렀을때 해당하는 랙 구성 화면으로 연결되게 하고 싶어. 지금은 SICAS와 EC/DSTT만 되는 거 같아. 그리고 현장설비와 기계실 설비를 점선으로 나누고 현장시설물(현장 선로전환기, 현장 신호기, 현장 ATO loop)들을 점선 밑으로 위치 조정해줘. ATO 분전반 줄바꾸고 (전원공급) 이라고 텍스트 조정해주고, 분전반 네모도 크기를 키워줘. 위치 조정하면서 전에 말했던 대로 화살표가 서로 겹치지 않게 해주고, 화살표에 적힌 글씨도 화살표를 가리지 않으면서도 해당 화살표에 대한 설명이라는걸 확실히 알 수 있게 해줘."

**① 모바일 핀치줌/드래그팬 신규 구현**

기존에는 시스템 지도가 고정 크기 SVG라서 모바일 화면에서 전체를 한 번에 보기 어려웠음. `.map-wrap`(고정 비율 뷰포트, `overflow:hidden`) 안에 `.map-pan`(실제 지도가 들어있는 레이어)을 두고, JS로 `translate(x,y) scale(s)`를 실시간으로 걸어주는 방식으로 확대/축소·이동 기능을 새로 구현함:
- 처음 열면 화면 크기(모바일/PC 공통 로직)에 맞춰 지도 전체가 뷰포트에 "한눈에" 들어오는 배율로 자동 조정(`mapFitScale`) — PC처럼 넓은 화면일수록 크게, 좁은 모바일 화면일수록 필요한 만큼만 축소.
- 손가락 두 개로 핀치줌(모바일), 마우스 휠(PC), 우하단 확대/축소/원래크기 버튼 3개 — 세 가지 방법 모두 지원. 확대는 커서/두 손가락 중심점 기준으로 이루어짐.
- 한 손가락 드래그(모바일 터치) / 마우스 드래그(PC)로 이동(팬) 가능.
- 드래그·핀치 동작 직후 발생하는 클릭이 그 아래 노드를 잘못 클릭한 것으로 처리되지 않도록 별도 처리(일정 거리 이상 움직였으면 그 뒤의 click 이벤트를 무시).
- `.map-wrap`의 세로 비율을 지도 원본 비율(1050:800)에 맞춰 `aspect-ratio`로 지정 — 기존에는 뷰포트 높이 비례(`68vh`)로 고정해서 모바일 세로 화면에서 지도 위아래로 빈 여백이 크게 남았는데(폭 기준으로 축소되다 보니 높이가 남음), 지도 원본 비율에 맞춰 뷰포트 크기 자체를 조정해 여백을 최소화함. (단, 화면이 아주 좁아 지도가 너무 작아지지 않도록 `min-height:260px` 최저치는 유지.)
- 화면 회전·창 크기 변경 시 자동으로 "한눈에 보기" 배율로 다시 맞춰짐.

**② 시스템 지도 노드 클릭 → 랙 구성 화면 연결 — 실제로는 12개 노드 중 7개가 이미 정상 동작 중이었음, 미연결 1건 신규 연결**

사용자는 "SICAS와 EC/DSTT만 되는 것 같다"고 느꼈지만, 실제로 코드를 전수 점검한 결과 SICAS·EC/DSTT·LZB700M·IFC·FTGS·TWC·ATO Loop 제어함 총 7개 노드는 이번 세션 이전부터 이미 정상적으로 해당 랙 구성 화면으로 연결되고 있었음(아마도 화면이 작아 클릭 반응이 잘 안 느껴졌거나, 다른 노드들과 헷갈리기 쉬웠던 것으로 추정). 나머지 노드는 아래와 같이 두 종류로 나뉨:
- **현장 ATO Loop(코일/C-B Box) — 미연결 상태였던 것을 신규 연결**: "ATO Loop 제어함" 그룹의 "현장설비" 탭으로 바로 이동하도록 새로 연결함(제어함 자체가 아니라 그 아래 "현장설비" 세부 탭으로 정확히 이동).
- **관제시스템·인접 연동역 SICAS·현장 선로전환기·현장 신호기·ID랙 — 랙 구성 화면 자체가 없는 노드**: 이 5개는 장비구성뷰에 대응하는 랙/캐비닛 데이터가 아예 없는 대상(관제시스템·인접역 등은 이 역의 설비가 아니고, 현장 선로전환기·신호기는 이번 범위에 랙 상세가 없음)이라 클릭하면 간단한 설명 패널만 뜨는 것이 맞는 동작 — 범례 문구에 "점선 테두리 상자는 아직 별도 랙 구성 화면이 없어 탭하면 간단한 설명만 보여줍니다"라고 명시해 사용자가 구분할 수 있도록 함.

**③ 기계실 설비 / 현장설비 점선 구분 + 현장시설물 재배치**

지도 중간에 점선(`stroke-dasharray`)을 긋고 좌우에 "기계실 설비" / "현장설비 (트랙사이드)" 라벨을 배치. 기존에 다른 기계실 노드들과 섞여 있던 "현장 선로전환기"·"현장 신호기"·"현장 ATO Loop 코일/C-B Box" 3개 노드를 점선 아래 한 줄로 재배치하고, 박스 테두리도 점선으로 표시해(`stroke-dasharray`) 시각적으로도 "현장설비"임이 구분되도록 함.

**④ ATO 분전반 박스 확대 + 줄바꿈**

라벨을 "ATO 분전반 (전원 공급)"에서 "ATO 분전반 (전원공급)"으로 수정(괄호 안 공백 제거)하고 박스 크기를 키워서, 기존 자동 줄바꿈 로직이 "ATO 분전반" / "(전원공급)" 두 줄로 자연스럽게 나뉘도록 함.

**⑤ 화살표(연결선) 재배치 — 겹침 0건 검증 + 라벨 가독성 개선**

③·④번 재배치에 맞춰 관련 연결선 4개(ATO 분전반→EC/DSTT, EC/DSTT→현장 선로전환기/현장 신호기, ATO Loop 제어함→현장 ATO Loop) 좌표를 다시 계산. 직접 만든 기하 검증 스크립트(모든 연결선 쌍의 선분 교차 여부 + 모든 연결선이 관계없는 다른 박스를 통과하는지)로 전수 검사해 **교차 0건·박스 통과 0건**을 확인함. 또한 라벨(선 위에 붙는 설명 텍스트) 렌더링을 "선 먼저 전부 그리기 → 박스 그리기 → 라벨 전부 마지막에 그리기" 순서로 바꿔서, 어떤 라벨도 다른 선에 가려지지 않도록 했고, 각 라벨 배경 상자·글자 색을 그 선의 케이블 색과 동일하게 맞춰 "이 라벨이 어느 선 설명인지" 한눈에 알 수 있도록 함(기존에는 라벨 색이 전부 동일해서 구분이 어려웠음).

**검증(Playwright)**: ① 노드 12개 전수 클릭 → 연결 여부 확인(7개 랙 이동 + 현장 ATO Loop 신규 이동 + 5개 랙 없음 확인, 전부 기대값과 일치). ② 화살표 겹침 검증 스크립트로 교차 0건·박스 통과 0건·화면 밖 이탈 0건 확인. ③ 모바일(390px) 실제 드래그·휠줌·버튼줌·두 손가락 핀치줌 시뮬레이션 — 전부 정상 작동 확인(초기 드래그 테스트에서 좌표 밖 클릭으로 오작동처럼 보였던 것은 테스트 스크립트 문제였고, 스크롤 위치를 맞춰 재검증한 결과 실제로는 문제 없었음). ④ 360px 폭에서 페이지 가로 스크롤(`scrollWidth`) 0건 확인. ⑤ 전체 회귀 스윕(12개 장비군 × 모든 탭 × 모든 드릴다운) 콘솔/런타임 에러 0건.

## 13. 시스템 지도 후속 보정 4건 — 초기 배율·ID랙 라벨 겹침·FTGS 줄바꿈·노드 색상 확대 (완료)

**사용자 피드백**(시스템 지도 미리보기 스크린샷 첨부): "확대축소는 잘되는데 왜 처음 장비구성뷰 키면 이렇게 작게 보이는거야? 장비구성뷰 열면 처음 딱 볼때 화면에 딱맞게 보이면 좋겠어. 그리고 ftgs와 id랙 사이 화살표는 텍스트 때문에 잘 안보이는데 id랙 크기를 줄이면 어떨까싶어. ftgs 줄바꿔서 (궤도회로 장치) 라고 텍스트 편집해주고 sicas와 ec/dstt 처럼 네모칸에 색깔을 입혀줘.(랙 구성에 있는 시설물에만 색상 넣어줘)"

**① 처음 열 때 지도가 작게 보이던 문제 — 원인은 `max-height:600px`가 폭까지 함께 제한하고 있었던 것**

§12에서 모바일 세로 화면의 여백을 줄이려고 `.map-wrap`에 `aspect-ratio:1050/800`(지도 원본 비율)을 걸면서 `max-height:600px`로 안전장치를 뒀는데, 이 요소가 실제로는 폭·높이가 서로 묶여 있어(비율 고정) 화면이 넓어도 높이가 600px에 걸리는 순간 폭까지 덩달아 작아지는 부작용이 있었음(예: 900px 이상 넓은 화면에서도 지도 박스가 786×598로 멈춤 — 화면이 더 넓어져도 전혀 안 커짐). `max-height`를 `min(760px, 78vh)`로 완화해 실제 콘텐츠 영역 폭(`.content` 최대 980px)까지는 자연스럽게 커지도록 하고, 화면이 짧은 경우(가로 모드 등)에는 `78vh`가 대신 상한 역할을 하도록 함. 결과: 좁은 모바일에서는 이전과 동일하게 여백 없이 꽉 차고, 넓은 화면(태블릿·PC)에서는 콘텐츠 영역 폭에 맞춰 지도가 훨씬 크게(최대 938×714) 보임 — "처음 열었을 때 화면에 딱 맞게" 요구사항 충족.

**② FTGS↔ID랙 화살표 라벨 겹침 — ID랙 박스를 줄이고 오른쪽으로 옮겨 간격 확보**

기존 ID랙 박스(폭 160)와 FTGS 박스 사이 간격이 35px밖에 안 돼서, 그 사이에 붙는 케이블 라벨("직결(실선)")이 양쪽 박스에 걸쳐 겹쳐 보였음. 사용자 제안대로 ID랙 박스 폭을 160→110으로 줄이고 위치도 오른쪽으로 옮겨서 FTGS와의 간격을 35px→90px로 넓힘(EC/DSTT 등 다른 박스와는 여전히 안 겹침 — 기하 검증 스크립트로 재확인). SICAS→ID랙 연결선도 새 박스 중심에 맞춰 좌표 보정.

**③ FTGS 라벨 줄바꿈 — "FTGS" / "(궤도회로 장치)" 두 줄로 강제 분리**

기존에는 라벨 안의 공백만 보고 자동으로 줄을 나누는 방식이라(ATO 분전반과 동일한 방식) "FTGS (궤도회로" / "장치)"처럼 어색하게 잘렸음. 이번에 `wrapLabel` 함수 자체를 개선해 라벨 문자열에 명시적 줄바꿈 지점을 지정할 수 있게 만들고, FTGS 라벨에 적용해 정확히 "FTGS" / "(궤도회로 장치)"로 나뉘도록 함. (참고로 이 개선 덕분에 앞으로 비슷하게 줄바꿈 위치를 지정해야 하는 라벨이 또 생기면 더 쉽게 처리 가능.)

**④ 랙 구성 화면이 있는 노드 전체에 색상 적용 — 임의 색이 아니라 기존 랙 탭 색상을 그대로 재사용**

기존에는 SICAS·EC/DSTT 딱 2개 노드만 하드코딩으로 색이 칠해져 있었고 나머지(LZB700M·IFC·FTGS·TWC·ATO Loop 제어함·현장 ATO Loop 포함)는 랙 구성 화면이 있는데도 무채색이었음. 새로 임의의 색을 만드는 대신, 랙 구성 탭에서 각 장비군 칩·헤더에 이미 쓰고 있는 고유 accent 색(`GROUPS[키].accent`)을 그대로 시스템 지도 노드 색으로도 재사용하도록 로직을 바꿔서, "랙 구성 화면이 있는 노드"(SICAS·EC/DSTT·LZB700M·IFC·FTGS·TWC·ATO Loop 제어함·현장 ATO Loop, 총 8개)는 전부 각자 고유 색으로, 그 외(관제시스템·인접역 SICAS·ID랙·ATO 분전반·현장 선로전환기·현장 신호기)는 기존처럼 무채색으로 남도록 함. 범례의 "SICAS/EC-DSTT" 개별 색상표 2개도 이제 맞지 않게 돼서 "색칠된 상자 = 랙 구성 화면 있음(장비군마다 다른 색)" 한 줄로 통합.

**검증(Playwright)**: 기하 검증 스크립트 재실행(교차 0건·박스 통과 0건 유지), 전체 회귀 스윕 에러 0건, 노드 12개 전수 클릭 결과 §12 때와 동일(변경 없음 확인), 360px 폭 가로 스크롤 0건, 드래그팬·휠줌·버튼줌·핀치줌 재확인 — 전부 정상. 데스크톱(1280px)·모바일(390px) 스크린샷으로 색상·라벨·간격 육안 확인.

**[참고] "ATO 분전반이 EC/DSTT 말고 다른 설비에도 전원공급 하지 않나?" 질문에 대해**: 현재 이 파일(`CONN.edges`)에는 ATO 분전반 → EC/DSTT 연결 1건만 기록되어 있고, 그 외 설비로 가는 전원 연결은 데이터에 없음(ATO_PANEL 노드의 note에도 "EC/DSTT에 60V/24V/110V 계통 전원을 공급하는 분전반"이라고만 되어 있음). 다른 설비에도 실제로 공급하는 게 맞다면 알려주시면 CONN.edges에 연결선을 추가하겠음 — 확인 없이 임의로 추가하지는 않음.

## 14. 시스템 지도 초기 배율 문제 재조사·재구현 — CSS aspect-ratio 대신 JS로 높이 직접 계산 + 화면맞춤 버튼 재배치 (완료)

**사용자 피드백**(모바일·PC 스크린샷 각 1장 첨부): "1번 사진은 모바일 화면으로 처음 장비구성뷰를 켰을때고, 2번 사진은 PC 화면으로 처음 장비구성뷰를 켰을때인데, 두 화면 다 처음 시스템지도가 화면에 꽉차지 않아. 다시 설정해줘. 그리고 확대,축소 하다가도 화면에 꽉찬 화면으로 돌아가는 버튼도 +,- 버튼 위에 하나 추가해줘."

**① 왜 §13에서 고쳤다고 확인했는데도 여전히 재현됐는가**

§13에서는 지도 박스(`.map-wrap`) 크기를 CSS `aspect-ratio:1050/800` + `max-height`로 지도 원본 비율에 맞춰 자동 계산하도록 했고, 제 쪽 테스트(Playwright/Chromium)에서는 여러 화면 폭에서 잘 맞는 것을 확인했었음. 그런데 사용자가 실제로 보는 화면(모바일 앱 미리보기, PC 브라우저)에서는 이 CSS 속성이 기대한 대로 적용되지 않아 박스 크기가 폭에 비해 훨씬 크게 남아(즉, 지도가 박스 안에서 위쪽 작은 영역에만 그려지고 나머지는 빈 공간) 재현됨 — 제가 테스트한 환경과 사용자의 실제 환경 사이에 `aspect-ratio` 속성 처리 방식 차이가 있었던 것으로 추정.

**② CSS 속성에 의존하지 않는 방식으로 재구현**

`aspect-ratio` CSS 속성을 아예 걷어내고, 지도 박스의 높이를 JS에서 직접 계산해 `style.height`에 못박는 방식(`mapSizeWrap()` 함수 신규)으로 바꿈: 박스의 실제 폭(`clientWidth`, 이건 일반적인 블록 레이아웃이라 어떤 환경에서도 항상 정확함)을 읽어서 지도 비율(1050:800)에 맞는 높이를 계산하고, 화면 세로 길이의 78%(`window.innerHeight*0.78`)와 760px 중 더 작은 값을 상한으로, 260px를 하한으로 두어 `style.height`에 직접 설정. 최신 CSS 기능(aspect-ratio, min() 등 조합)에 기대는 대신 아주 기본적인 계산 + 직접 대입 방식이라 브라우저·환경에 상관없이 동일하게 동작함.

**③ 확대/축소 후 "화면에 꽉 차게" 버튼 — 기존 버튼을 위로 재배치 + 아이콘 교체(중복 추가 아님)**

기존에도 우하단 세 번째 버튼(⤢, "원래 크기")이 정확히 이 기능(화면 맞춤 배율로 복귀)을 하고 있었음 — 다만 유니코드 글자(⤢)라 의미가 잘 안 보였을 수 있음. 완전히 같은 동작을 하는 버튼을 하나 더 추가하면 중복이라, 대신 이 버튼을 +/− **위**로 옮기고, 아이콘을 네 모서리 화살표 모양(화면 맞춤을 나타내는 보편적인 아이콘, SVG로 직접 그림 — 유니코드 글자보다 렌더링이 안정적)으로 바꿈. 혹시 "복귀 버튼"과 "확대/축소 버튼"을 완전히 분리된 두 그룹으로 따로 두길 원하시면 말씀해주시면 그렇게 바꾸겠음.

**검증(Playwright)**: 모바일 좁은 폭(390px)부터 넓은 데스크톱 폭(1280px)까지, 그리고 가로모드 같은 낮은 화면(844×390)까지 포함해 여러 조합에서 지도 박스가 항상 지도 비율에 맞게 꽉 차는지 확인(낮은 화면에서는 세로 78% 상한이 정상적으로 작동해 잘림 없이 축소됨). 화면맞춤 버튼(재배치된 것) 클릭 시 정확히 원래 배율로 복귀하는지, 드래그팬·휠줌·핀치줌·360px 가로 스크롤 0건까지 전부 재확인. 기하 겹침 검증 스크립트·전체 회귀 스윕도 재실행해 이상 없음 확인.

## 15. 지도 초기 배율 문제 3차 대응 — "왜 자꾸 재현되는지" 확실히 못 밝힌 채, 원인 불문 자동 보정 구조로 전환 (완료, 단 미해결 가능성 있음 — 아래 참고)

**사용자 피드백**: "여전히 같은 현상이야. ㅠㅠ 왜 자꾸 그러지. 결과물을 보여주기 전에 너가 확실히 화면에 꽉차게 나오는지 확인해보고, 검토한 다음에 결과물을 줘. 여전히 모바일, PC화면에서 다 작게 보여."

**솔직한 상황 설명**: §13·§14에서 각각 다른 방식(CSS `aspect-ratio` → JS로 높이 직접 계산)으로 고쳤다고 판단했던 근거는 전부 이 세션 안에서 Playwright(자동화된 헤드리스 브라우저)로 직접 렌더링해 측정한 결과였음 — 여러 화면 폭(360px~1280px)에서 지도 박스가 정확히 꽉 차는 것을 실측으로 확인했었음. 그런데도 사용자가 실제로 보는 화면에서는 계속 작게 보인다는 건, 제가 테스트하는 환경과 사용자가 파일을 여는 실제 환경(미리보기 방식·기기·브라우저) 사이에 제가 아직 파악하지 못한 차이가 있다는 뜻. 이 차이의 정체를 정확히 특정하지 못한 채 "이번엔 이 방식으로 하면 되겠지"라고 추측성 수정을 반복하는 건 비효율적이라고 판단해, 이번엔 접근을 바꿈.

**바뀐 접근: 원인을 특정하지 못해도 스스로 계속 다시 맞추도록**

기존에는 지도 탭을 열 때 "박스 크기를 한 번 측정 → 그 값으로 배율 계산 → 끝"이었음(그 한 번의 측정이 어떤 이유로든 틀리면 그걸로 고정되어버림). 이번엔 아래 두 가지를 추가해 "측정이 언제 정확해지든 그 시점에 자동으로 다시 맞추는" 구조로 바꿈:

1. **`ResizeObserver`** — 지도 박스(#mapWrap) 자체의 실제 렌더링 크기가 바뀌는 모든 경우(이유를 정확히 몰라도 됨 — 미리보기 프레임이 로드 후에 크기를 늦게 확정하는 경우, 폰트 로딩으로 주변 레이아웃이 나중에 밀리는 경우 등 전부 포함)를 실시간으로 감지해서, 사용자가 아직 직접 확대·축소·이동을 하지 않은 "처음 연 상태" 동안에는 계속 자동으로 화면 맞춤 배율을 다시 적용하도록 함.
2. **다음 프레임 재확인(requestAnimationFrame ×2)** — `ResizeObserver`를 지원하지 않는 구형 환경을 위한 추가 안전장치로, 화면이 그려진 직후 한두 프레임 뒤에 한 번 더 맞춤 배율을 재계산.

사용자가 실제로 확대·축소 버튼을 누르거나 드래그·핀치를 하면 그 순간부터는 자동 보정을 멈추고 사용자가 만든 배율/위치를 그대로 유지함(그렇지 않으면 사용자가 확대한 걸 자꾸 되돌려버리게 됨). "화면에 꽉 차게" 버튼을 다시 누르면 자동 보정 상태로 복귀.

**검증(Playwright)**: 이번엔 "정상적으로 처음부터 정확한 크기가 측정되는" 시나리오뿐 아니라, 일부러 컨테이너 폭을 실제보다 좁게 만들어놓고(예: 200px로 강제) 지도 탭을 연 다음, 별도의 재계산 호출 없이 컨테이너 크기를 나중에 올바르게 되돌리는 시나리오로도 테스트함 — `ResizeObserver`가 이 "늦게 정확해지는" 경우를 실제로 감지해서 자동으로 배율을 다시 맞추는 것을 확인(758px 폭 컨테이너 기준 올바른 배율 0.6912로 자동 보정됨). 또한 사용자가 수동으로 확대한 뒤에는 컨테이너 크기가 바뀌어도 그 수동 배율이 그대로 유지되는 것도 확인. 기존 기능(기하 겹침 0건, 전체 회귀 스윕, 노드 클릭 12개, 360px 가로 스크롤 0건, 드래그·휠줌·핀치줌)도 전부 재확인.

**⚠️ 솔직히 말씀드릴 점**: 이 수정이 실제로 사용자 환경의 근본 원인을 없앤 것인지, 아니면 또 다른 추측인지는 이 세션 안에서 100% 확신할 수 없음(제 쪽에서는 사용자가 보는 것과 동일한 미리보기 환경을 직접 재현할 방법이 없음). 만약 이번에도 같은 현상이 재현된다면, 다음 중 어떤 방식으로 파일을 열어보시는지 알려주시면 원인을 훨씬 정확히 좁힐 수 있음: (a) 채팅창에 뜨는 파일 미리보기 화면으로 보시는지, (b) 다운로드해서 휴대폰/PC의 실제 브라우저(Chrome/Safari 등)로 직접 여시는지, (c) 그 경우 어떤 기기·브라우저인지. 이 정보가 있으면 "제가 테스트하는 환경 vs 사용자 환경"의 정확한 차이를 재현해볼 수 있음.

## 16. 지도 초기 배율 문제 — 진짜 원인 특정·재현·수정 확인 (완료)

**사용자 피드백**: "1번 사진은 다운받아서 브라우저에서 열어봤을때고 2번 사진은 클로드에서 미리보기로 봤을때야. 둘 다 모바일에서 열어봤을때인데 여전히 안고쳐지고 있어. pc화면에서도 여전히 똑같고." (다운로드 후 실제 모바일 브라우저로 직접 연 스크린샷 첨부)

**이번엔 추측이 아니라 실측으로 접근함**: 사용자가 보내준 스크린샷 2장을 픽셀 단위로 직접 분석함(Python으로 이미지를 열어 지도 박스 테두리·버튼·다이어그램 각각의 정확한 픽셀 좌표를 찾아 실제 크기·비율을 역산). 그 결과 **지도 박스(#mapWrap) 자체는 정확히 올바른 크기(폭 대비 높이 비율 1.322, 기대값 1.3125로 사실상 일치)로 렌더링되고 있었고, 화면 폭의 93.5%를 정상적으로 채우고 있었음** — 즉 §14·§15에서 고친 "박스 크기 계산" 자체는 이미 제대로 동작하고 있었다는 뜻. 문제는 그 박스 **안의 다이어그램(SVG)** 이 박스 대비 약 1/3 크기로만 그려지고 있다는 것으로 좁혀짐(픽셀 실측: 실제 렌더링 배율 ≈0.114, 계산상 나와야 할 배율 ≈0.330 — 정확히 약 3배 차이).

**진짜 원인**: 전역 CSS 규칙 `img,svg{max-width:100%}`(줄 29 — 원래 랙 구성 화면 등 다른 곳의 일반 이미지가 컨테이너 밖으로 안 튀어나오게 하려고 넣어둔 규칙)가 지도 SVG(`.map-svg`)에도 그대로 적용되고 있었음. 지도 SVG는 `width="1050" height="800"` 속성으로 원래 크기를 갖도록 만들어졌는데, 이 전역 규칙 때문에 폭만 박스 크기(예: 367px)로 강제로 줄어들고 **높이는 800px 그대로 남아** — 즉 SVG 자체가 원래 비율(1050:800)이 아니라 완전히 눌린 비율(367:800)로 먼저 한 번 찌그러진 채 렌더링됨. 그 위에 JS(`mapApplyTransform`)가 "박스에 맞는 배율"로 계산한 `transform:scale()`을 또 한 번 곱하다 보니, 이미 폭이 1/3로 줄어든 상태에 배율이 다시 곱해져 결과적으로 다이어그램이 원래 있어야 할 크기의 몇 분의 1로 작게 보였던 것.

**왜 지난 세 번의 시도(§13~§15)에서 못 잡았는지**: 지난 테스트는 전부 일반 데스크톱 Chromium 브라우저 창 크기만 좁혀서 "모바일처럼" 흉내 낸 것이었는데, 이 방식으로는 이 버그가 재현되지 않음(데스크톱 Chromium은 이 CSS 상황을 다르게 처리하는 것으로 보임). 이번엔 Playwright의 **실제 모바일 기기 프로필**(Pixel 5 등 — 터치·모바일 렌더링 경로를 실제로 흉내 내는 설정)로 테스트해서 그제서야 정확히 재현됨 — 재현 화면에서 SVG의 계산된 폭이 실제로 "367px"(박스 폭과 동일, 100% 제한에 걸림)로 나오고 높이는 "800px"(그대로)로 나오는 것까지 직접 확인.

**수정**: `.map-svg`에 `max-width:none` + `width:1050px;height:800px`를 명시해서, 전역 `img,svg{max-width:100%}` 규칙이 지도 SVG에는 적용되지 않도록 예외 처리. 이제 SVG는 항상 원래 비율(1050×800) 그대로 렌더링되고, 그 위에 JS 배율만 한 번 곱해져 정확한 크기로 보임.

**검증(Playwright, 실제 모바일 기기 프로필로 재검증)**: 고치기 전 상태로 되돌려 Pixel 5 프로필에서 버그가 정확히 재현되는 것을 먼저 확인(SVG 계산 폭 367px/높이 800px로 찌그러짐, 실제 렌더링 크기 122×267 — 사용자 스크린샷과 동일한 증상)한 뒤, 수정을 다시 적용해 SVG가 항상 1050×800 원래 비율로 렌더링되고 박스를 95~96% 채우는 것을 확인. 추가로 iPhone 13·Galaxy S9+·Pixel 7 등 여러 실기기 프로필로도 재검증 — 전부 박스의 95~96%를 채움(세로가 짧은 기기는 세로 78% 상한 때문에 83% 정도로 약간 낮게 나오는 게 정상 동작). 기존 기능(기하 겹침 0건, 전체 회귀 스윕, 노드 클릭 12개, 360px 가로 스크롤 0건, 드래그·휠줌·핀치줌, ResizeObserver 자동 보정)도 전부 재확인 — 전부 정상.

## 18. 측정지점·전원흐름·랙 구성 — 제목 좌측 카메라 아이콘 + 사진 빠른보기(퀵프리뷰) 팝업 신규 (완료)

**사용자 요청**(측정지점 탭 스크린샷 1장 첨부): "측정지점 탭에서 '전원전압 구동 DC 60V' 우측에 회색 글씨로 작게 있는 정상범위 전압값 글씨를 키워달라. 그리고 지금은 설명 밑에 실물 사진 넣는 곳이 있는데, 여기 말고 제목 좌측에 카메라 아이콘을 넣어서 누르면 사진이 확대/축소 가능한 팝업으로 보이고 우측 상단에 X로 닫을 수 있게 해달라. 전원흐름 탭에는 '숫자 - 카메라 아이콘 - 제목' 순서로, 랙 구성 탭에는 각 행(레벨) 제목 좌측에 카메라 아이콘을 넣어달라. 애매한 부분은 물어보고 진행해달라."

**먼저 확인한 것**: 애매한 부분 4가지를 질문으로 여쭤서 확인받고 진행함 — ① 여러 장 매칭되면 첫 장을 보여주고 팝업 안에서 다음/이전으로 넘기기, ② 매칭되는 사진이 0장이면 곧바로 "폴더 열기" 창을 띄우기, ③ 기존 "실물 사진/동영상" 섹션(마커 편집용)은 그대로 두고 카메라 아이콘은 빠른 미리보기용으로 추가, ④ 랙 구성 탭은 각 행(레벨) 목록의 제목 옆에만 적용(보드 상세 페이지 제목에는 중복 적용 안 함).

**① 정상범위 배지 글씨 확대**: 측정지점 카드 제목 우측의 회색 정상범위 값(예: "42~75 V")의 `font-size`를 11px → 13.5px로 키움. 제목 텍스트(15px 안팎)에 비해 여전히 작게 대비되지만, 이전보다 또렷하게 읽힘.

**② 카메라 아이콘 — 새로 만들지 않고 기존 사진 매칭 로직(`galleryFoldersFor`)을 그대로 재사용**: 3개 탭 모두 각 항목마다 이미 존재하던 사진 매칭 방식(측정지점·전원흐름은 기존 `renderPhotoSection()`이 쓰던 것과 동일한 sectionId·groupKey, 랙 구성은 각 행마다 `cabrow:<그룹키>:<행번호>`라는 새 sectionId를 붙여 그룹 단위 자동 매칭은 그대로 적용됨)를 그대로 써서, 카메라 아이콘을 누르면:
- 매칭되는 사진이 1장 이상 있으면 → 퀵프리뷰 팝업을 그 사진(들)로 염.
- 0장이면 → 바로 "사진/동영상 폴더 열기" 창이 뜸(질문 ②번 답변대로).

아이콘 배치: 측정지점은 제목 span 왼쪽(요청대로), 전원흐름은 `숫자 뱃지` 바로 뒤·제목 텍스트 앞(숫자→카메라→제목 순서, 요청대로), 랙 구성은 각 행의 라벨 텍스트 왼쪽(보드 썸네일 이미지가 있는 행은 썸네일 뒤·라벨 앞에 위치 — "제목 좌측"이라는 요청 그대로 유지하면서 기존 썸네일 배치는 건드리지 않음). 아이콘 버튼 자체가 `data-act="qpopen"`을 갖고 있어서, 클릭 이벤트가 부모(제목 접기/펼치기 버튼, 행 드릴다운 버튼 등)로 전파되지 않고 카메라 아이콘 클릭만 정확히 처리됨(측정지점 카드가 같이 접히거나 랙 구성 행이 같이 드릴다운되는 등의 오작동 없음 — Playwright로 확인).

**③ 퀵프리뷰 팝업 — 기존 마커 편집 모달과는 완전히 별도로 새로 구현**: 기존 사진 모달(`photoModalRoot`, 마커 찍기·이름/메모 편집용)은 확대/축소·이전/다음 기능이 없어서(사진이 항상 박스에 꽉 차게 고정 표시) 그대로 재사용할 수 없었음. 그래서 마커 편집 기능 없이 순수 "보기 전용"인 별도의 가벼운 팝업(`quickPreviewRoot`, 전용 `qpView`/`qpStage` 엔진)을 새로 만듦:
- 손가락 두 개로 핀치 확대/축소, 확대한 상태에서는 한 손가락으로 끌어서 이동, 더블탭(또는 더블클릭)으로 1배↔2.5배 전환, PC에서는 마우스 휠로 확대/축소 — 지도 탭의 확대/축소 방식과 비슷한 방식으로 새로 구현.
- 우측 상단 X 아이콘으로 닫기(요청대로), 배경(어두운 바깥 영역) 클릭으로도 닫힘, 여러 장 매칭 시 하단에 "‹ 1/2 ›" 형태의 이전/다음 버튼.
- 사진 전환 시(다음/이전) 확대·이동 상태는 자동으로 초기화됨.
- 기존 "실물 사진/동영상" 섹션(`renderPhotoSection`)은 코드 한 줄도 건드리지 않음 — 그대로 남아있고 마커 편집·폴더 추가 기능도 그대로 동작함(질문 ③번 답변대로, 두 UI가 서로 다른 목적으로 공존).

**검증(Playwright)**: 구문 검사·회귀 스윕(에러 0건) 재실행. 신규 기능 전용 시나리오 테스트 — 측정지점 탭 카메라 아이콘 개수, 정상범위 배지 폰트 크기, 사진 0장일 때 폴더 열기 창이 뜨는지(파일 선택창 트리거 확인)·이때 카드 접기/펼치기가 같이 발생하지 않는지, 가짜 사진 2장을 주입한 뒤 카메라 아이콘 클릭 시 퀵프리뷰가 뜨는지·다음/이전 버튼·마우스 휠 확대·확대 상태에서 드래그 이동이 실제로 반영되는지·X 버튼과 배경 클릭 둘 다로 닫히는지, 닫은 뒤 기존 "실물 사진/동영상" 섹션(썸네일 2장 포함)이 그대로 남아있는지, 전원흐름 탭 제목의 자식 요소 순서가 실제로 "숫자→카메라" 순서인지, 랙 구성 탭 카메라 아이콘 클릭이 행 드릴다운을 같이 일으키지 않는지 — 전부 정상 확인. Pixel 5 모바일 프로필로 3개 탭 스크린샷과 퀵프리뷰 팝업 스크린샷을 직접 눈으로도 확인함(레이아웃 깨짐·잘림 없음).

## 19. 측정지점 카드 제목 세로 찌그러짐 버그 수정 + 안내 배너 전체를 화면 맨 아래로 재배치 (완료)

**사용자가 발견한 버그**(스크린샷 5장 첨부): 측정지점 탭에서 제목("ATO 컨트롤러 송신전압", "현장송신전압", "현장수신전압", "수신-1 PCB 입력전압(I5/I8)" 등)이 세로로 한 글자씩 찌그러져 여러 줄에 걸쳐 표시되는 버그. 정상범위 값("증폭보드 9~12 V / 필터보드 30~90 V" 등)이 긴 항목에서만 나타남.

**원인**: `.stage-title`이 `display:flex`이고 제목 span에 `flex:1`(= `flex-basis:0`)만 줘서, 카메라 아이콘 + 긴 정상범위 값 텍스트가 같은 줄에서 공간을 다투면 브라우저가 제목 span을 극단적으로 좁게(때로는 몇 px까지) 줄여버림. 한글은 영어와 달리 공백 없이도 글자 하나하나가 줄바꿈 지점이 될 수 있어서, 이렇게 폭이 초소형으로 줄어들면 "한 글자당 한 줄"로 세로로 쌓여 보이는 것. 갱신본 22에서 카메라 아이콘을 추가하고 정상범위 폰트를 키우면서(11px→13.5px) 제목이 차지할 수 있는 공간이 더 줄어들어 이 잠재 버그가 실제로 터진 것으로 보임(카메라 아이콘 폭 + 커진 배지 폭이 겹쳐 임계점을 넘음).

**수정**: `.stage-title`에 `flex-wrap:wrap`을 추가하고 제목 span에 `min-width:140px`를 지정해, 한 줄에 다 들어가지 않으면 제목이 찌그러지는 대신 정상범위 값이 **다음 줄로 자연스럽게 줄바꿈**되도록 바꿈(`.stage-title>.mono{margin-left:auto}`로 줄바꿈됐을 때도 오른쪽 정렬 유지). 같은 3단 구조(즐겨찾기 버튼+증상 텍스트+분류 배지)를 쓰는 고장상황 탭의 카드 제목에도 동일한 잠재 버그가 있어 예방 차원에서 함께 수정.

**안내 배너 전체 재배치**: "노란색"(v3 시안 안내, `renderGlobalBanner()`)과 "파란색"(각 탭 첫머리 안내문, `.banner.info`/`.banner.warn`) 텍스트박스를 화면 맨 위(콘텐츠보다 먼저 보이던 위치)에서 **화면 가장 하단**으로 전부 옮김 — 사용자 요청대로 **5개 탭 전부**(시스템 지도·랙 구성·전원흐름·측정지점·고장상황) 적용. 랙 구성 탭은 하위 3가지 화면 종류(캐비닛형·FTGS 보드1열형·개념도형) 전부 포함. 보드 상세/행 상세 페이지에 걸리는 노란 배너도 동일하게 맨 아래로 이동(전역 배너라 `render()` 한 곳만 수정하면 모든 화면에 공통 적용됨). 각 탭 안에서 "먼저 콘텐츠를 보고, 필요하면 아래에서 안내문 참고"하는 순서가 됨.

**검증(Playwright)**: 문제가 재현됐던 LZB700M 그룹의 측정지점 카드들을 실제 모바일 화면(Pixel 5)에서 스크린샷으로 확인 — 제목이 모두 정상적으로 가로 한 줄(또는 자연스러운 가로 줄바꿈)로 보이고, 긴 정상범위 값은 제목 아래 줄에 오른쪽 정렬로 표시됨. 전체 12개 측정지점 카드 제목의 렌더링 높이를 코드로 측정해 비정상적으로 큰(세로로 찌그러진) 카드가 0건임을 확인. 5개 탭 전부에서 안내 배너 2개가 각 탭 콘텐츠의 가장 마지막 자식 요소로 위치하는지 코드로 검증(전부 정상). 구문 검사·전체 회귀 스윕·갱신본 22 카메라 기능 테스트 전부 재실행해 이상 없음 확인.

**[참고] 발견했지만 이번 요청과 무관해서 손대지 않은 항목** → **사용자 확인 후 해소(같은 날 추가 수정)**: 측정지점 탭 LZB700M 그룹의 "캐비닛 내부 온도 측정"이 "undefined~40 ℃"로, "ATO Loop전원케이블 절연저항 측정"이 "1~undefined MΩ"로 표시되던 건, 사용자 확인 결과 **데이터 자체는 원래부터 맞았음**(온도는 "40℃ 이하"만 있고 하한 없음, 절연저항은 "1MΩ 이상"만 있고 상한 없음 — measure-points.json의 값 그대로). 문제는 표시 로직 쪽이었음: `measurePointSummary()`(카드 목록의 회색 배지)와 `renderMpDetail()`(펼쳤을 때 "정상범위" 줄) 둘 다 `min~max` 형식만 가정하고 있어서, 둘 중 하나가 없는 항목을 "undefined"라고 그대로 이어붙였던 것. 이미 같은 문제를 올바르게 처리하고 있던 `thresholds`용 `thresholdText()` 함수(하한만 있으면 "○ 이상", 상한만 있으면 "○ 이하"로 표기)를 `range`에도 그대로 재사용하도록 통일해서 해결 — 데이터 수정 없이 표시 로직만 고쳐서 "40 이하 ℃", "1 이상 MΩ"로 정확히 나오는 것을 카드 배지·펼친 상세 둘 다에서 확인함.

## 20. 모바일에서 카메라 아이콘이 반응 없던 버그 — 원인 특정·수정 (완료)

**사용자 질문**: "왜 모바일에서는 카메라 버튼 눌렀을 때 아무반응이 없어?"

**원인**: 카메라 아이콘을 눌렀을 때 그 항목에 매칭되는 사진이 이 브라우저 세션에 아직 하나도 안 불러와져 있으면(사진은 파일 안에 저장되지 않고 매번 폴더를 직접 열어야 나타나는 방식이라, 앱을 새로 열면 항상 이 상태), 기존 "사진/동영상 폴더 열기"와 동일한 폴더 선택창(`<input type="file" webkitdirectory>`)을 자동으로 띄우도록 되어 있었음. 그런데 이 "폴더 선택" 기능은 PC 브라우저(Chrome/Edge)에서는 되지만 **아이폰 사파리·안드로이드 크롬 등 모바일 브라우저에서는 지원되지 않아**, 탭해도 아무 UI가 뜨지 않고 조용히 실패함. 사용자 확인 결과 실제로 "이번 세션에서 사진을 처음 불러오려던 상황"이었던 것으로 확인되어 이 가설이 재현 조건과 정확히 일치함. 이 문제는 카메라 아이콘만의 문제가 아니라 기존 "사진/동영상 폴더 열기" 버튼도 모바일에서는 동일하게 안 됐을 것으로 보이는 문제.

**수정**: 사용자가 "모바일에서는 사진 여러 장 직접 선택으로 대체" 방식을 선택함.
- 기기 판별용 `isMobileDevice()` 함수 신규 추가(User-Agent 기반).
- 카메라 아이콘 전용 `openPhotoPickerDirect(sectionId, groupKey, label)` 함수 신규 추가 — 모바일에서 사진이 0장일 때, 폴더 선택 대신 `<input type="file" multiple accept="image/*,video/*">`(폴더 속성 없음)로 갤러리에서 사진/동영상 여러 장을 직접 고르게 함. 고른 파일은 이 항목 전용 폴더("측정지점 제목 (직접 선택)" 형태로 이름 붙임)에 담고, 폴더명 매칭에 기대지 않고 `photoManualFolders[sectionId]`에 확실하게 등록해서 이 항목의 갤러리·퀵프리뷰에 항상 뜨도록 함. 로드가 끝나면 방금 고른 사진을 바로 볼 수 있도록 퀵프리뷰를 자동으로 엶.
- 기존 "사진/동영상 폴더 열기" 버튼(`openPhotoPicker()`, 상단·각 갤러리 섹션에 공통으로 쓰임)도 같은 문제를 갖고 있어 함께 수정 — 모바일에서는 `webkitdirectory` 속성을 빼고 일반 다중 선택(`accept="image/*,video/*"`)으로 열리도록 해서, 최소한 사진은 고를 수 있게 함(폴더 구조가 없으니 기존 코드의 기본 동작대로 "사진"이라는 공용 폴더에 담김 — 그 뒤 "+ 다른 폴더에서 사진 선택…" 드롭다운으로 원하는 항목에 수동 연결 가능). PC에서는 두 버튼 모두 기존과 100% 동일하게 폴더 선택 방식 유지.
- 카메라 아이콘에 항목의 제목(측정지점 제목/전원흐름 단계명/랙 구성 행 라벨)을 `data-label`로 함께 실어 보내도록 `cameraIconBtn()`을 확장 — 모바일에서 직접 고른 사진의 폴더 이름이 "SICAS" 같은 막연한 이름이 아니라 "단자 이완 및 조임부분 점검 (직접 선택)"처럼 실제 항목 제목으로 붙어서, 나중에 갤러리 목록에서 어떤 사진 묶음인지 알아보기 쉽게 함.

**검증(Playwright, 실제 모바일 기기 프로필 Pixel 5로 재현·수정 확인)**: 수정 전 상태에서는 재현하지 않고(이미 코드 수정 완료 후 테스트), Pixel 5 프로필(안드로이드 모바일 User-Agent + 터치)에서 카메라 아이콘을 눌렀을 때 뜨는 파일 선택창이 실제로 `webkitdirectory`/`directory` 속성 없이 `accept="image/*,video/*"`·`multiple`로만 구성되어 있는지 확인(정상), 가짜 이미지 파일을 골라 넣었을 때 해당 항목 전용 폴더가 생성되고 `photoManualFolders`에 정확히 등록되며 로드 직후 퀵프리뷰가 자동으로 열리는 것까지 확인. 데스크톱(1280px, 일반 UA)에서는 기존과 동일하게 `webkitdirectory` 속성이 그대로 붙어서 뜨는 것도 재확인(회귀 없음). 지난 회차의 카메라 아이콘·퀵프리뷰 전체 테스트도 재실행해 이상 없음 확인. 구문 검사·전체 회귀 스윕도 재실행함.

**[참고] 모바일에서 여전히 확인이 어려운 부분**: `isMobileDevice()`는 User-Agent 문자열 기반 판별이라 100% 완벽하지 않을 수 있음(예: 데스크톱 모드로 보는 일부 태블릿 등은 PC로 인식되어 폴더 선택 방식이 뜰 수 있음) — 만약 특정 기기에서 여전히 문제가 있으면 기기 종류를 알려주시면 판별 조건을 보강하겠음.

## 22. "이 장비에 사진 지정" 신규 기능 + 퀵프리뷰 마커 표시 + 보드 이미지 보드에도 사진 섹션 항상 노출 (완료)

**사용자 제보 3건** (스크린샷 4장 첨부 — 랙 구성 화면 캡처 2장 + 카메라 아이콘으로 연 사진 갤러리 팝업 캡처 2장): "카메라 아이콘을 누르니 폴더 안에 있는 사진 전체가 다 보이더라고. 내가 원하는 장비에 내가 원하는 사진만 딱 보이게 하고 싶은데 조치부탁해. 그리고 마커 찍은것도 카메라 아이콘 눌러서 보면 마커가 안보여. 그리고 보드 이미지가 있는 곳은 사진을 넣고 마커를 놓을 수 없었어. 보드 이미지가 있는 곳에도 사진을 넣을 수 있도록 해줘." (+ PC/모바일 간 사진 동기화 여부 질문)

**① 원인 — "그룹(캐비닛) 전체" 단위로만 사진을 매칭하던 설계**

기존 `galleryFoldersFor(sectionId, groupKey)`는 사진 폴더를 **groupKey**(예: "EC/DSTT", "SICAS" — 캐비닛/시설물 전체)로만 매칭했다. sectionId(보드 하나, 행 하나, 측정지점 하나, 전원흐름 단계 하나처럼 훨씬 더 좁은 단위)는 "수동으로 폴더 하나를 통째로 추가"할 때만 쓰였을 뿐, 자동매칭 자체는 항상 그룹 전체 폴더를 가리켰다. 그 결과 예를 들어 "EC/DSTT" 폴더에 캐비닛 사진 37장이 들어있으면, 그 그룹에 속한 모든 보드·행의 카메라 아이콘/사진 갤러리가 전부 그 37장을 그대로 보여줬다 — 이게 "원하는 장비의 원하는 사진만" 보고 싶다는 요구를 채울 수 없었던 근본 원인. (기존 주석에도 "그룹 단위로 사진을 매칭하므로 같은 그룹의 다른 보드에서도 동일한 갤러리가 보이는 것이 정상"이라고 의도적으로 설계돼 있었으나, 실제 사용해보니 불편하다는 것이 이번에 확인됨.)

**해결 — sectionId 단위로 사진 몇 장만 직접 골라 연결하는 "이 장비에 사진 지정" 기능 신규 추가**

- 모든 사진 섹션(보드 상세페이지, 랙 구성 행, 측정지점, 전원흐름 단계 — 전부 이미 고유한 sectionId를 갖고 있었음, 예: `board:SICAS_VESUV3`, `mp:MP_FTGS_AMP_OUT`)의 "📷 실물 사진/동영상" 영역에 **"🖼 이 장비에 사진 지정"** 버튼을 새로 추가.
- 누르면 지금까지 불러온 사진/동영상 전체를 폴더별로 나열한 체크박스 팝업(`photoCurateRoot`)이 뜬다. 여기서 이 항목에 보여줄 사진만 체크하면 되고, 체크한 순간부터 **이 항목의 갤러리·카메라 아이콘 퀵프리뷰 둘 다 자동매칭 전체 대신 체크한 사진만** 보여준다("🖼 이 장비에 지정한 사진 N장만 표시 중" 안내 + "지정 해제" 버튼으로 언제든 자동매칭으로 복귀 가능).
- 다른 항목(다른 보드 등)에는 전혀 영향 없음 — sectionId별로 독립적으로 지정. 같은 사진을 여러 항목에 동시에 지정하는 것도 가능(예: 캐비닛 전경 사진 1장을 그 안의 여러 보드에 공통으로 연결).
- 아무것도 지정하지 않은 항목은 기존과 동일하게 그룹 전체 자동매칭 방식 그대로 동작(하위호환 — 갑자기 사진이 안 보이게 되는 일 없음).
- 이 지정 정보(`photoManualItems`)는 마커·메모와 동일하게 이 브라우저에 localStorage로 best-effort 저장되고, "작업 JSON 내려받기" 파일(`photo-markers-export.json`, schemaVersion 2.2로 갱신)에도 `sectionPhotoAssignments` 필드로 함께 담겨서, 다음 세션에 병합 요청 시 그대로 반영 가능.

**② 카메라 아이콘 퀵프리뷰에 마커 표시 추가 (읽기 전용)**

기존 퀵프리뷰(갱신본 22에서 신규 구현)는 "빠르게 훑어보기"용으로 마커 표시 자체가 없었음(마커 편집은 기존 사진 갤러리 썸네일 클릭 → 마커 모달에서만 가능). 이번에 퀵프리뷰 사진 위에도 찍혀있는 마커를 번호 핀 + 이름표로 겹쳐 보여주도록 추가(편집은 여전히 안 됨 — 편집하려면 기존 갤러리에서 사진을 눌러 마커 모달을 열어야 함, 역할 분리 유지). 확대/축소·이동(pinch/pan) 시에도 마커가 사진과 함께 정확히 움직이도록, 이미지가 실제로 그려지는 픽셀 크기·위치를 JS로 계산해(`qpRecalcBox()`) 그 기준으로 마커를 배치하고 확대/이동 transform도 그 박스에 걸었다(기존에는 `<img>` 자체에 transform을 걸었는데, `object-fit:contain`으로 인한 레터박스 여백까지 고려하면 퍼센트 좌표가 어긋날 수 있어 별도 박스 방식으로 변경).

**③ 실물풍 이미지가 있는 보드도 사진/마커 섹션 항상 노출**

기존엔 `!realImg || info.forcePhotoSection` 조건으로, 실물풍 SVG 이미지가 이미 만들어진 보드는 `forcePhotoSection: true`가 켜진 일부(현장설비 C/B박스 등)만 예외적으로 사진 섹션이 보였고 나머지 대다수(SICAS/EC-DSTT/LZB700M 등 이미지화된 52개 보드)는 사진 섹션 자체가 안 보였음 — "보드 이미지가 있는 곳은 사진을 넣고 마커를 놓을 수 없었다"는 제보와 정확히 일치. 이 조건을 없애고 **모든 보드 상세페이지에 사진 섹션을 항상 노출**하도록 변경. 위 ①의 "이 장비에 사진 지정" 기능과 결합하면, 이미지화된 보드라도 그 보드의 실측 사진을 정확히 골라 붙이고 마커를 찍을 수 있음.

**④ PC ↔ 모바일 사진 동기화 질문에 대한 답**

이 앱은 서버가 없는 순수 브라우저 앱이라(§3 설계 방향 참고), "사진/동영상 폴더 열기"로 불러온 사진 원본은 **그 브라우저 탭의 메모리에만 올라가고 어디로도 전송되지 않는다.** 즉:
- PC에서 넣은 사진은 PC의 그 브라우저 세션에만 존재 — 휴대폰에서는 안 보임(반대도 마찬가지).
- 같은 기기·같은 브라우저에서도 페이지를 새로고침하면 사진 자체는 다시 폴더를 열어야 함(사라지는 건 아니고, 마커·메모·이번에 추가된 "사진 지정" 정보는 localStorage에 남아있어서 같은 폴더를 다시 열면 자동으로 다시 연결됨).
- 여러 기기에서 보이게 하려면: (a) 사진 폴더 자체를 Google Drive/OneDrive 같은 동기화 폴더에 두고 각 기기에서 그 동기화된 폴더를 각자 열거나, (b) "작업 JSON 내려받기"로 마커·사진지정 정보만이라도 내려받아 보관 후 다음 세션에 프로젝트에 병합 요청하는 방법(사진 원본 자체의 영구 저장/동기화는 이 앱 설계상 지원하지 않음).

**검증(Playwright)**: 가짜 이미지(data URI)로 폴더를 흉내 내어 ① 실물풍 이미지가 있는 보드(SICAS_VESUV3) 상세페이지에도 사진 섹션이 뜨는지, ② 사진 지정 전에는 그룹 전체 자동매칭 사진(5장)이 다 보이다가 "이 장비에 사진 지정"으로 1장만 체크하면 갤러리·카메라 아이콘 퀵프리뷰 둘 다 정확히 그 1장만 보이는지, ③ 마커 모달에서 마커를 추가하면 갤러리 썸네일 배지(●1)와 퀵프리뷰 오버레이 핀에 모두 반영되는지, ④ 측정지점 탭에서도 sectionId(`mp:...`) 단위 지정이 동일하게 동작하는지, ⑤ "지정 해제"를 누르면 원래 자동매칭 전체(예: 3장)로 정확히 복귀하는지, ⑥ 사진이 0장 매칭될 때 카메라 아이콘을 누르면 기존과 동일하게 폴더/사진 선택창이 뜨는지(회귀 없음) — 전부 정상 확인. 모바일 폭(390px)에서 전체 12개 그룹 × 5개 탭 순회 회귀 스윕도 재실행해 가로 스크롤 0px·콘솔/런타임 에러 0건 확인.
