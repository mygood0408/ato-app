# 세션 S3 인수인계서 — 역 확장 설계 + PDF 인벤토리 (2026-09-29)

공통 규칙·원본 목록·결정: `claude/세션_로드맵_2026-09-29.md` 를 먼저 읽을 것. 선행: S2 결과.

## 목표 (설계 문서 중심, 코드 변경 최소)
1. **PDF 인벤토리**: 15개 SICAS + 12개 ATP 문서별로 쪽수, 시스템 구분(SIN1/2, SNU1/2, SON1/2, SPO1/2), 제목 블록의 역명·캐비닛명(S51/S52 등)·도면번호 접두(`=SIN1/…` 규칙)를 스크립트로 추출해 표 1장(`claude/역_인벤토리.md`). KB `04_index`, `05_reports/GAP_ANALYSIS`, `FINAL_REPORT`를 먼저 참고(재계산 금지).
2. **구조 결정(사용자와 확인 후 문서화)**:
   - 역 키 규칙: `relatedDrawings` 키 = KB 문서 접미사(SIN1, SIN2, SNU1 …) 유지(D 결론). 역(station)↔시스템(접미사) 매핑 테이블 1개 추가 여부.
   - 데이터 분리: 역 공통(장비 종류 설명) vs 역별(경로·도면 쪽·캐비닛명·단자번호). `power-paths.json`·`board-info.json`·`rack-layout.json` 각각 어디를 역별로 나눌지.
   - 경로 id 규칙: 현재 `..._SIN2` 접미. 다른 역도 같은 규칙으로 갈지.
   - 템플릿/인스턴스 분리 여부: S2에서 알게 된 다른 역 도면 구조 차이로 판단. 기본은 "스크립트 역 인자만 추가"(C4 방식) 유지.
   - SNU/SON/SPO의 시스템 1·2가 SIN1/SIN2와 같은 템플릿인지(SIN2·SON2 150쪽) 도면 제목 텍스트 유사도로 간단 검증.
3. **스크립트 일반화 설계**: `make_power_paths*.py`, `sync_related_drawings.py`에서 SIN1→SIN2 하드코딩된 곳 목록(grep)과 "역 목록 인자" 인터페이스 초안.

## 하지 않을 것
