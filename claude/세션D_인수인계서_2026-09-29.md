# 세션 D 인수인계서 — SIN2 도면 쪽수 연결 (2026-09-29)

## 목표 (이것만)
- 도면 쪽수 연결 필드를 **역별 구조**로 바꾸고 SIN2 쪽수를 추가. SIN2 고유 내용(단자·전압·랙 배치)은 넣지 않는다.
- 신도림(SIN1) 기준 텍스트가 다른 역에 그대로 보이면 현장 오해 위험 → 화면에 "신도림(SIN1) 기준 설명 · 이 역은 도면 확인" 표시.

## 알려진 사실
- 현재 `board-info.json` 보드별 `relatedDrawings[]` = `[{doc:"ATP_HW_Design_SIN1", pages[], totalPagesFound, note}, {doc:"SICAS_HW_Design_SIN1",...}]` (38개 보드).
- 지난 세션 시범(읽기 전용): SIN1 연결 38개 보드가 SIN2 도면에서도 같은 키워드로 38/38 검색됨. SIN2 도면 분량: ATP_HW_Design_SIN2 100쪽, SICAS_HW_Design_SIN2 150쪽 (SIN1은 228/286쪽).
- 키워드 규칙(지난 스크립트): 보드 id에서 접두어 제거한 부분 + 보드명 첫 단어(3자 이상)로 페이지 md + `03_ocr` 텍스트 검색. **키워드가 걸린다고 내용이 같은 것은 아님** → 결과는 전부 "자동매칭 · 확인필요".
- SIN1과 SIN2가 같은 역의 두 시스템인지 다른 역인지는 **미확인** — 시작 시 사용자에게 물어볼 것(작업량·표시 문구에 영향).

## 작업 순서
1. 구조 제안 후 사용자 확인: 예) `relatedDrawings: { "SIN1": [...], "SIN2": [...] }` (기존 배열은 SIN1로 이동). 화면 코드(`renderKbRefs` 호출부, 세션 B 이후라면 뷰어 연결부)가 읽는 모든 곳을 grep으로 먼저 파악하고 같이 수정.
2. 스크립트로 SIN2 매칭(같은 규칙) → 개수 요약만 보고. 페이지 원문 덤프 금지.
3. (선택, 사용자 동의 시) SIN1↔SIN2 페이지 텍스트 자동 비교로 "차이 큰 보드" 목록만 뽑아 보고 — 고유 내용을 다룰 후보.
4. 역 선택 UI가 필요한지는 사용자와 논의(이 세션에서는 최소한 표시만).
